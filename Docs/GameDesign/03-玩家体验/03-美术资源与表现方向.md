# 美术资源与表现方向

> 状态：复用与重做边界已确认；最终资源由独立美术 OpenSpec 管理

## 文档边界

本文只记录玩法对美术和表现的稳定需求，不替代 Art Bible、具体资源需求表、切图规格或 Prefab 制作说明。程序与美术通过稳定资源 ID、槽位和 fallback 解耦。

## 当前复用资源

### 场景

- 第一张地图 OasisCity 已完成搭建，场景风格已经确认。
- OasisCity 是当前唯一权威玩法地图。
- 继续使用现有 3D 场景、建筑和环境资源。
- 玩法位置由场景中显式 PlayerSpawn、MapResource 和 Extraction 锚点提供。

### 角色

- 当前采用 3D 角色路线。
- 旧 2D 角色帧、动画和对应映射不再使用。
- 功能阶段可使用 Capsule 或稳定 3D fallback，但最终角色表现另行验收。

### 纹身

- 已确认的 8 个几何黑工图案继续使用。
- First Playable 只接入 P01/P02。
- 图案尚未获得正式名称，美术文件名和 UI 不应代替策划命名。
- 纹身需要支持身体部位挂接、元素颜色和对外情报图标。

## 必须重新设计的资源

### UI

旧 UI 对应角色选择、商店、多武器、随时修改纹身和旧流程，已不符合新需求。需要围绕以下界面重新设计：

- MainMenu 和本地对局确认。
- 纹身与元素档案、玩法帮助、Settings、Credits。
- CombatHUD。
- 五次构筑界面。
- 六人情报面板。
- 颜料请求。
- 倒地、救援、淘汰和观战。
- 五轮结果与测试撤离结果。

UI 美术需要以 `rebaseline-pvpve-art-resources` 的 layout、资源键和交付索引为准。

### 枪械与 VFX

- 单步枪最终模型、图标和材质可替换当前 fallback。
- 火、冰、雷状态需要层级可读表现。
- 热冲击、过载、停滞需要彼此可区分的反应反馈。
- 弱点命中、普攻相关右臂、主动技能相关左臂、倒地、救援和撤离需要独立反馈层。

## 纹身表现要求

- 图案轮廓在角色运动和常用镜头距离下仍可辨认。
- 元素颜色不能破坏原始图案形状。
- P01/P02 在 HUD、构筑界面和六人情报中使用一致的图形标识。
- 不依赖图案正式名称完成识别。
- 未来 P03～P08 保留资源接口，但当前不出现在活动可装备清单。

## 元素可读性

元素反馈至少同时使用两种通道，例如颜色 + 图标、颜色 + 形状或粒子 + 音效，避免只依赖色相。

层级需要可辨认：

- 弱层：基础提示。
- 标准层：明显增强但不遮挡目标。
- 强层：最高警示，同时保持瞄准和弱点可见。

反应必须与元素常驻状态区别，避免玩家误以为新元素仍留在目标身上。

## 弱点表现

- 玩家弱点是头部，可通过命中反馈强化，不必长期发光。
- 非人型 Enemy 的弱点未来可由 Shader、预制体发光物、材质结构或动画表达。
- 弱点提示方式必须在 Enemy 设计时与攻击节奏共同确定。

## 占位与正式验收

- 最终美术不阻塞玩法闭环和自动 smoke。
- 缺失资源使用明确 fallback，不允许 Missing Reference。
- 占位资源只能标记“功能可运行”，不能标记“视觉验收完成”。
- UI 数据或交互 bug 在程序 change 修复；布局、切片、色彩和最终效果偏差回到美术 change。
