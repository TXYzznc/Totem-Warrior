# 事件队列与成果归因

> 状态：顺序与归因规则已确认并实现

## 系统目的

一次行为可能同时满足弱点、普攻右臂、主动技能左臂、躯干、元素和其他条件。如果所有效果立即互相调用，最终顺序会依赖脚本调用链，同一帧中难以解释、测试和表现。

事件队列把“哪些效果合法”和“按什么顺序结算”分开处理，使相同 seed 与输入产生可重复结果，也允许每个事件之间加入仅用于表现的短暂延迟。

## 单次行为的结算流程

```text
收到合法行为
→ 建立本次 Resolution Context
→ 完成基础命中和有效直接伤害
→ 收集所有满足条件的效果事件
→ 按优先级降序排列
→ 同优先级按 seed 派生顺序洗牌
→ 逐个重新检查并结算
→ 记录伤害、状态、击倒、淘汰和成果
→ 输出表现指令
```

## 事件优先级

| 优先级 | 事件 | First Playable 状态 |
|---:|---|---|
| 100 | 主动技能相关左臂 | 活动；左臂纹身授予对应主动技能 |
| 90 | 闪避 | 已保留 |
| 80 | 移动 | 已保留 |
| 70 | 头部弱点 | 活动 |
| 60 | 普攻相关右臂 | 活动；当前步枪普攻要求造成有效直接伤害 |
| 50 | 躯干 | 活动/保留 |

优先级表示同一次行为中的结算顺序，不代表长期强度或 UI 排序。

## 同优先级随机

- 同优先级事件不使用代码注册顺序。
- 使用 `matchSeed + resolutionSequence` 派生确定性随机顺序。
- 相同 seed、输入和事件集合必须得到相同顺序。
- 不同对局允许出现不同顺序，避免固定注册顺序形成隐藏偏向。

## 逐项结算

事件入队时合法，不代表结算时必然仍合法。前一个事件可能使目标倒地、淘汰、移位或失去状态。因此每项事件执行前需要按规则重新确认目标和上下文。

不过，表现延迟不能让现实帧时间改变模拟结论。队列的模拟顺序已经确定，视觉只按该结果播放。

## 表现延迟

- 事件之间可以配置短暂延迟，让玩家识别连续效果。
- 延迟为 0 的快速模式和默认演出模式必须产生相同生命、状态、击杀、统计和队列顺序。
- 延迟不推进元素时间、缩圈、Bot 决策或其他战斗模拟。
- 不通过全局反应冷却限制事件数量。

## 反应归因

当 A 先施加已有元素、B 再施加异元素触发反应：

- B 是反应触发者。
- A 是被消费元素层的辅助来源。
- 如果反应造成淘汰，最终淘汰归 B。
- A 和 B 的本局成果都增加相同数值的间接元素伤害。
- 实际目标生命只扣除一次。
- 两人都显示“间接造成 X 点元素伤害”。

此设计同时承认准备元素和完成反应的贡献，但保留最后触发者对击杀结果的责任。

## 直接、间接与团队成果

- 直接枪械伤害只计算实际造成的正数伤害。
- 反应伤害作为间接元素伤害单独呈现。
- 多方贡献记录不代表复制真实伤害。
- 为队友创造的增伤、控制、护盾和减伤分别进入对应成果字段。
- 同队无效伤害不进入任何正向成果。

## 为什么当前禁止反应链

允许反应生成新事件可能产生有趣的涌现，但也会带来：

- 无限循环。
- 同状态重复触发。
- 队列指数增长。
- 击杀与辅助来源传播不清。
- 一次命中产生过长的不可控演出。

因此 First Playable 的反应是终止节点。反应链保留在想法库，待现有系统经过多轮 PVP 实测后再设计链深、预算和去重规则。

## 诊断与证据要求

开发证据应能够记录：

- match seed 和 resolution sequence。
- 收集到的事件集合。
- 排序后的队列。
- 每项事件的执行、跳过或失效原因。
- 直接与间接伤害。
- 元素来源和被消费层。
- 最终击倒、淘汰与多方成果。
