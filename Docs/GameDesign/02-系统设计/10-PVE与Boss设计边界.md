# PVE、Enemy 与 Boss 设计边界

> 状态：宏观目标部分确认；具体玩法暂未设计  
> 重要：当前项目运行时按纯 PVP 实现，旧 Enemy/PVE/Boss 方案已取消并清理。

## 为什么当前不实现

此前 Enemy、Encounter、EnemyLoot 和 Boss 实现来自旧产品假设，与新的六人、双排、五轮构筑和后半局撤离目标没有经过统一设计。继续保留会造成两个问题：

1. 旧实现看似节省时间，实际会反向限制新玩法。
2. 测试当前 PVP 构筑时，无法判断问题来自枪战、纹身、Bot 还是未经确认的 PVE 压力。

因此 First Playable 把 Enemy、遭遇、敌人掉落、Boss 和敌人弱点从运行时、配置、测试、诊断和资源入口中移除。

## 当前仍然保留的通用能力

- 伤害与成果归因的通用概念。
- 元素、反应和效果队列的通用结构。
- OasisCity 合法锚点 authoring 思路。
- 撤离服务的一次性权威解锁入口。
- 玩家头部弱点和未来弱点表现方向。

保留这些通用能力不等于 Enemy 已实现，也不能在活动 UI 中展示空的 PVE 统计。

## 已确认的长期 PVE 目标

- PVE 主要增强 PvPvE 中的“E”，为探索和发育提供主动目标与压力。
- Enemy 应在前三轮支持资源争夺和路线选择，而不是完全替代玩家间对抗。
- Enemy 数量、职责和弱点必须适配 6 人、3 队和单开发者生产力。
- 非人型 Enemy 的弱点需要 Shader、高亮对象、材质或动画等明确提示。
- Enemy 掉落应进入新的地图/奖励经济，不恢复旧 EnemyLoot 假设。

## 已确认的长期 Boss 目标

- 第三次缩圈后、第四轮战斗开始时在随机合法区域刷新。
- 强度适合多名玩家共同挑战。
- 参战者过少可能无法击败，从而出现所有剩余玩家无法撤离的失败局面。
- Boss 被击败后才解锁撤离点。
- 根据玩家综合贡献给予局内属性强化。
- 最后一击玩家获得额外特殊效果。
- 同时刷新高阶资源，吸引愿意承担风险的玩家留到第五轮。

## 需要重新设计的问题

### Enemy

- 需要几种职责才能支持发育、区域控制和路线差异？
- Enemy 是否会主动追击、守卫资源还是响应玩家行为？
- 三队同时存在时，仇恨和目标选择如何避免被利用？
- Enemy 能否对所有队伍公平提供信息和反制窗口？
- 击杀、助攻、控制和掉落如何归因？
- 如何避免 PVE 成为刷资源的无风险最优路线？

### Boss

- Boss 的阶段、能力和多人挑战人数基准。
- Boss 区域如何预警，如何避免出生位置偏向某队。
- 玩家间伤害始终开放时，Boss 行为如何处理多队目标。
- 综合贡献算法包含哪些行为，如何防止刷无效贡献。
- 最后一击效果多强才不会否定其他贡献。
- Boss 超时、所有玩家倒地或人数不足时如何结算。

### 奖励与撤离

- 高阶资源的种类、数量和局外价值。
- 提前撤离与第五轮高风险收益的期望差。
- 圈外撤离点的失效提示和可达性。
- 正式联机中一队撤离后其他队如何继续。

## 后续工作规则

PVE 与 Boss 必须建立新的设计讨论和 OpenSpec change。新方案需要先回答玩家目标、MDA、节奏、内容量、异常规则和验收标准，再进入实现；不得直接从 Git 历史恢复旧模块作为临时版本。
