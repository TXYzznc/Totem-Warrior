# 系统关系总图

> 状态：核心关系已确认  
> 文档职责：定义主要玩法对象、系统职责和跨系统数据流。

## 核心概念

| 概念 | 定义 | 主要作用 |
|---|---|---|
| 参赛者 | 一局中的真人或 Bot 战斗单位 | 移动、攻击、构筑、拾取、救援、撤离并产生本局成果 |
| 队伍 | 两名参赛者组成的合作单位 | 共享胜负关系和撤离结果，但不自动共享颜料 |
| 对局 | 由 seed、6 名参赛者、3 支队伍、阶段、地图与结果组成的一次运行 | 提供确定性规则与生命周期边界 |
| 构筑 | 六个身体部位上的图案与元素组合 | 改变事件触发和战斗效果 |
| 颜料 | 火、冰、雷三种个人局内资源 | 装备纹身、形成元素方向，也可经队友请求转移 |
| 构筑快照 | 每次构筑开始时冻结的全员信息 | 为玩家提供反制依据，避免实时镜像修改 |
| 元素状态 | 目标身上的火、冰、雷弱/标准/强层级及来源 | 提供持续特性、反应与成果归因 |
| 效果事件 | 一次行为产生、等待排序结算的合法结果 | 保证同时触发时的顺序、确定性和表现空间 |
| 地图锚点 | OasisCity 中显式配置的合法位置 | 分别用于队伍出生、地图资源和撤离点生成 |
| 撤离 | 队伍主动离开对局的成功路径 | 长期由 Boss 解锁；First Playable 由测试事件解锁 |
| 本局成果 | 从开局累计到当前边界的个人贡献数据 | 公开表现、支持反制和最终结果证据 |

## 系统关系

```text
OasisCity 合法锚点 + Match Seed
        ├─→ 三支队伍出生
        ├─→ 每轮地图资源生成
        └─→ 解锁后撤离点生成

战斗与探索
  ├─→ 当前枪械普攻 ─→ 弱点 / 普攻相关右臂事件
  ├─→ 颜料拾取 ─────→ 个人库存
  ├─→ 元素施加 ─────→ 层级 / 持续 / 反应
  ├─→ 致命伤害 ─────→ 倒地 / 救援 / 淘汰
  └─→ 所有有效行为 ─→ 本局成果累计

进入构筑阶段
  ├─→ 未救起倒地者立即淘汰
  ├─→ 冻结六人构筑与成果快照
  ├─→ 暂停战斗世界
  ├─→ 修改纹身 / 请求颜料
  └─→ 倒计时结束后恢复战斗

最终状态
  ├─→ 仅剩一队：立即结算
  ├─→ 第五轮结束：按规则排名
  └─→ 本地队撤离：First Playable 立即结算
```

## 权威时序

`MatchFlow` 是阶段推进的唯一权威。UI、枪械、元素、Bot、缩圈、地图资源和撤离服务只能读取当前阶段或提交合法命令，不能自行跳过阶段。

构筑暂停以阶段门控为准，而不是只依赖全局 `timeScale`。这样 UI 倒计时、异步界面和诊断仍可运行，同时所有战斗模拟保持冻结。

## 必须保持的边界

- 一局必须恰好存在 6 名参赛者和 3 支互不重叠的双人队。
- 真人与 Bot 使用同一层 gameplay command 和规则校验。
- 同队无直接、元素和反应伤害。
- 纹身只能在构筑阶段修改。
- 构筑情报是阶段边界快照，不是实时监控对手编辑。
- 颜料属于个人库存，队友转移必须经过请求与批准。
- 元素层保存来源，不能在反应发生时临时猜测贡献者。
- 同次行为产生的效果先收集、再排序、再逐项结算。
- PlayerSpawn、MapResource、Extraction 三类锚点不得相互替代。
- First Playable 不注册或生成 Enemy、Encounter、EnemyLoot 和 Boss。
- 所有按键输入必须经过 InputModule 对应的项目输入服务。
- UI 与最终美术可以替换，但不能改变玩法阶段、资源和伤害合同。

## 长期扩展关系

未来 Boss 被击败时复用现有撤离权威解锁入口；正式联机只替换参赛者来源、命令传输与结算持续策略，不应重写构筑、元素、锚点和撤离交互规则。
