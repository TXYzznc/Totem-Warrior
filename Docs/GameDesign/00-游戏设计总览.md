# 游戏设计总览

> 状态：核心方向已确认；First Playable 已实现，等待持续试玩验证  
> 文档职责：说明游戏是什么、玩家在一局中做什么，以及当前版本如何验证长期方向。

## 一句话概念

一款 6 人、3 支双人队参与的分轮构筑撤离对抗游戏：玩家使用枪械战斗，在暂停的构筑阶段利用纹身图案、身体部位和火冰雷元素调整方案，并根据公开的全员构筑与本局成果反制对手；长期版本通过 Boss、PVE 和高阶资源把合作、背叛、风险与撤离选择集中到后半局。

## 游戏形态

- 对局人数：6 名参赛者。
- 队伍结构：3 支双人队。
- 补位方式：玩家不足时由 Bot 补齐。
- 当前运行模式：本地单人 + 5 Bot；无后端和真实网络同步。
- 核心战斗：使用单一基础步枪战斗；正式 3D 角色资源尚未制作，当前功能验证只能使用不冒充正式美术的运行时代理。镜头与最终操作视角尚未在本策划库中完成正式定义。
- 核心成长：局内探索获得颜料，在指定构筑阶段修改六部位纹身。
- 长期类型：PvPvE 撤离对抗。
- First Playable 类型：五轮纯 PVP 本地验证切片，附带测试版撤离事件。

## 核心体验

玩家不只是在战斗中比较枪法，也在每轮之间阅读整个对局：谁的构筑已经成形，谁的成果领先，谁频繁倒地，哪支队伍可能在下一轮改变策略。玩家用这些信息决定自己要继续强化优势、针对主要威胁、补足队伍短板，还是转向更适合撤离的方案。

游戏希望形成以下感受：

- “我看懂了对手上一阶段的意图，并提前做了应对。”
- “这个构筑不是绝对更强，但更适合现在的对局。”
- “我的操作、走位和弱点命中弥补了纸面数值差距。”
- “队友的构筑和资源与我互补，我们一起完成了反应或救援。”
- “继续争夺还是立刻撤离，是一次真实的风险收益选择。”

## 核心差异化

### 分轮公开情报

构筑不是战斗中随时改动的即时菜单。每轮构筑开始时，系统冻结并公开所有玩家在阶段边界前的构筑和整局累计成果。玩家在有限准备时间内做判断，新的修改到下一次构筑才会被其他人看到。

### 不固化流派标签

纹身不被强制标记为“突破、阵地、游击”等职业式流派。身体部位、图案、元素和触发事件组成规则，实际流派由玩家搭配和对局环境自然产生。

### 三角克制与操作修正并存

设计追求可读的三角克制关系，但不把胜负简化为选对克制。命中弱点、站位、反应触发时机、队友协作和资源管理应允许高操作玩家扩大普通构筑的上限。

### 后半局集中风险

长期版本的前三轮主要用于探索、发育和有限冲突；第四轮通过 Boss 迫使多队围绕共同目标聚集；第五轮通过高阶资源、缩小安全区和可能失效的撤离点制造最终冲突。

## 宏观对局循环

```text
读取地图与对手局势
→ 构筑阶段选择纹身和元素
→ 战斗、探索、拾取颜料、救援队友
→ 缩圈改变空间关系
→ 新构筑阶段公开上一边界快照
→ 根据对手成果与方案进行反制
→ 后半局完成目标并解锁撤离
→ 在安全撤离和继续争夺之间选择
→ 淘汰、撤离或最终结算
```

## 当前 First Playable 的验证问题

当前版本不是完整产品，而是验证以下问题：

1. 6 人、3 支双人队是否足以产生可读且不空旷的对抗关系？
2. 五轮构筑与战斗是否能形成“观察—调整—验证”的节奏？
3. 只用一款枪械时，纹身、元素和操作能否提供足够差异？
4. 全员情报是否能促进反制，而不是造成信息过载或机械抄答案？
5. 三元素、三层状态和反应队列是否清楚、稳定且具有团队协作空间？
6. 倒地、救援和无友伤能否让双人队真正形成合作单位？
7. 即使没有最终 UI、美术、后端、PVE 和 Boss，一局是否已经结构完整并可重复运行？

## 当前阶段

`rebuild-six-player-pvpve-first-playable` OpenSpec 已完成并归档。当前运行时已经形成六人双排、五轮纯 PVP、单步枪、构筑、情报、三元素、事件队列、倒地救援、地图资源和测试撤离闭环。

下一阶段重点不是恢复旧 PVE，而是先实际试玩当前闭环，验证节奏、信息量、构筑差异和操作空间；Enemy、Boss、高阶资源和正式联机分别进入新的设计与 OpenSpec change。
