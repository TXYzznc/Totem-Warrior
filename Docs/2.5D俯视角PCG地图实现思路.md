# 2.5D 俯视角 PCG 地图实现思路

> 目标：整理“2D 地面 + 2.5D 站立对象 + PCG 可交互地图”的设计思路，供后续会话继续讨论或拆成 Unity 实现方案。

## 1. 核心判断

不要把这类地图当成“纯 2D Tilemap 游戏”来做，而应该当成：

```text
2D 逻辑地图 + 2.5D 站立对象表现 + 美术指导型 PCG
```

底层世界仍然是 2D：

```text
- 地形格子
- biome 区域
- 可走 / 不可走
- 对象占位
- 交互点
- 路径连通性
```

画面表现是 2.5D：

```text
- 地面是 2D tile / mesh / 贴花
- 树、石头、建筑、道具是立起来的 sprite
- 站立对象按脚点排序
- 碰撞和交互只看地面 footprint
```

关键不是“用 2D 模拟 3D”，而是：

```text
2D 逻辑负责规则；
竖向 sprite 负责美术错觉；
资源语义负责 PCG 的可控性。
```

## 2. 为什么纯 2D 会觉得难

如果直接用 Tilemap 同时承担地面、美术、对象、碰撞、交互和遮挡，会很快遇到问题：

```text
- 树的图片很高，但碰撞只应该在树干底部
- 建筑看起来占很大画面，但地面 footprint 可能只是几格
- 角色走到树后面时需要被树冠遮挡
- 地面 tile 需要自然过渡，不能像格子拼图
- PCG 随机铺 tile 很容易破坏美术风格
- 特色地表资源不适合逐格随机使用
```

所以应该把职责拆开：

```text
地面层：表现地貌和基础可读性
贴花层：打散重复感，制造自然感
站立对象层：制造空间层次和交互内容
逻辑层：负责可走、占位、生成规则、连通性
```

## 3. 地面层如何无缝拼接

最重要的原则：

```text
chunk 是加载单位，不是生成单位。
```

不要这样做：

```text
生成地图 A -> 生成地图 B -> 再想办法把边缘缝起来
```

应该这样做：

```text
用同一个 world seed 和全局坐标生成整个世界；
再按 chunk 切片加载和显示。
```

也就是每个格子的地形都来自同一个函数：

```text
terrain = F(worldX, worldY, seed)
```

这样相邻 chunk 的边界天然来自同一套世界数据，不会出现“两个地图硬拼”的裂缝。

### 3.1 多层地形场

地面不要只生成一个 terrainType，可以先生成多层连续字段：

```text
- height：高度 / 陆地轮廓
- moisture：湿度
- temperature：温度
- danger：危险度
- fertility：肥沃度
- biomeWeight：生态区权重
```

再由这些字段推导：

```text
- 草地
- 泥地
- 水域
- 沙地
- 沼泽
- 森林地表
- 道路
```

### 3.2 边界多采样一圈

chunk 显示 32x32 时，不要只计算 32x32。

应该多计算边界辅助数据：

```text
显示区域：32x32
辅助采样：34x34 或 36x36
```

多出来的一圈用于判断边缘邻居，给 autotile / Wang tile / 过渡贴图使用。

```text
[隐藏边界数据][显示区域][隐藏边界数据]
```

否则 chunk 边缘不知道隔壁是什么地形，容易出现断边和错边。

### 3.3 生态区不要硬切

不要让草原和森林这样拼：

```text
草草草草草 | 森森森森森
```

更自然的结果应该是：

```text
草地 -> 草地带灌木 -> 稀疏树林 -> 密林
```

实现上不要只存一个离散 biome，而是存权重：

```text
grassWeight
forestWeight
swampWeight
```

程序根据权重决定：

```text
- 地面基础图
- 过渡 tile
- 贴花类型
- 对象密度
- 对象候选池
```

## 4. 美术资源不能让程序“自动理解”

如果地形美术资源比较有特色，程序不能凭空判断“这张图应该用在哪里”。

正确方式是：

```text
美术 / 设计定义资源语义和拼接规则；
程序生成地图意图；
规则系统把地图意图翻译成具体美术资源。
```

这叫：

```text
Art-directed PCG
美术指导型程序生成
```

PCG 不是替代美术设计，而是把美术设计变成一套可组合的“地图语法”。

## 5. 地形资源应该语义化

每个地形资源不应该只是一张 sprite，而应该是一个“带语义的地形部件”。

示例：

```text
Forest_Ground_01
- biome: forest
- terrain: grass
- moisture: medium/high
- useCase: inner
- edgeType: none
- allowedNeighbors: forest, grassland_transition
- forbiddenNeighbors: water_direct
- densityBias: tree +20%
```

水边泥地示例：

```text
Mud_Water_Edge_03
- biome: swamp
- terrain: mud
- useCase: water_edge
- edgeDirection: north/east/south/west
- allowedNeighbor: water
- decorateWith: reed, wet_stone
```

程序不是随机挑图，而是在问：

```text
这里是什么生态区？
这里是什么地面？
这里靠近水吗？
这里在道路边吗？
这里是生态核心区还是过渡区？
周围邻居是什么？
```

然后从符合条件的资源池里挑选。

## 6. 资源组织方式

建议按 Biome Kit 组织资源。

```text
Grassland Kit
- base ground
- transition
- patch / stamp
- decal
- standing object

Forest Kit
- base ground
- transition
- patch / stamp
- decal
- standing object

Swamp Kit
- base ground
- transition
- patch / stamp
- decal
- standing object
```

每个 kit 内部资源分四类：

```text
1. 基础地貌层
   低存在感，可重复，可大面积铺底。

2. 地面过渡层
   解决草地到泥地、泥地到水、森林到草原等边界。

3. 特色地表块
   手绘感强，有明显形状，适合作为 stamp / patch 放置。

4. 贴花与站立对象
   草斑、碎石、落叶、裂纹、树、石头、建筑、采集物。
```

## 7. 有特色的地表资源不要高频随机铺

越有特色的地面图，越不适合当普通 tile 高频随机使用。

错误倾向：

```text
每个格子都随机选择一张很有特色的地面图。
```

结果通常会变得：

```text
- 画面太碎
- 风格失控
- 拼接痕迹明显
- 每块图都在抢注意力
- 地图不像自然生成，而像贴图乱铺
```

更好的做法是：

```text
基础地面保持相对克制；
特色资源作为 stamp / patch / POI 地表块使用；
贴花和站立对象负责打散重复感。
```

例如：

```text
3x3 树根地表 stamp
5x5 蘑菇地毯 stamp
不规则泥潭 stamp
道路转角 stamp
水岸特殊 stamp
遗迹地面 stamp
```

放置 stamp 时检查：

```text
- 区域尺寸是否够
- 底层地形是否匹配
- 是否会覆盖道路
- 是否会堵住关键路径
- 周围是否需要留白
- 是否会破坏生态区风格
```

## 8. 推荐的地图表现分层

```text
宏观：程序生成
- 岛屿轮廓
- biome 分布
- 水域
- 道路
- 资源区
- 危险区
- POI 位置

中观：规则化美术拼接
- autotile
- Wang tile
- transition tile
- stamp / patch

微观：受控随机
- 贴花
- 小草
- 落叶
- 小石头
- 草丛
- 局部装饰
```

这样能同时保留：

```text
- PCG 的自由度
- 美术风格的可控性
- 地图区域的辨识度
- 资源复用效率
```

## 9. 如何判断哪里适合放置 2.5D 站立对象

不要靠随机点直接撒对象，而应该先为每个格子或区域计算“适宜度”。

每个格子可以有这些信息：

```text
- terrainType：草地 / 水 / 泥地 / 路
- biomeType：森林 / 草原 / 沼泽
- biomeWeight：生态权重
- distanceToWater：离水距离
- distanceToRoad：离路距离
- distanceToSpawn：离出生点距离
- distanceToPOI：离关键点距离
- isWalkable：是否可走
- isOccupied：是否已被占用
- localDensity：附近对象密度
- noiseValue：局部随机扰动
```

每种对象有自己的放置规则。

树的规则示例：

```text
适合：
- 森林 biome
- 草地 / 泥地
- 不在道路上
- 离水不要太近
- 可以和其他树形成聚集

不适合：
- 水里
- 出生点太近
- 路径中央
- 已经被建筑或石头占用
```

石头的规则示例：

```text
适合：
- 荒地 / 山地 / 矿区
- 离道路稍远
- 可以小范围聚集

不适合：
- 森林过密处
- 水边过近
- 阻断主路径
```

浆果的规则示例：

```text
适合：
- 草原 / 森林边缘
- 玩家可达区域
- 离出生点可以有少量
- 周围留出交互空间

不适合：
- 深水
- 建筑 footprint 内
- 完全被障碍包围
```

通用评分方式：

```text
最终适宜度 =
地形匹配
* biome 匹配
* 距离条件
* 密度条件
* 随机噪声
* 可达性检查
* 占位检查
```

## 10. 站立对象要分清三个概念

2.5D 对象不要用图片尺寸做逻辑占位。

必须拆成：

```text
spriteBounds：图片看起来有多大
footprint：地面上实际占几格
interactionRange：玩家站多远能交互
```

例如一棵树：

```text
spriteBounds：很高，很宽，有树冠
footprint：树干底部 1x1 或 1x2
interactionRange：周围一圈
```

如果用整张树图判断占位，森林会很难生成，也会很难走。

正确方式：

```text
视觉遮挡按 sprite 和脚点处理；
移动碰撞按 footprint 处理；
交互按 interactionRange 处理。
```

## 11. 推荐放置顺序

对象生成最好有顺序，不要所有对象混在一起随机撒。

```text
1. 必须存在的东西
   出生点、主路径、关键 POI、出口、营地。

2. 大型阻挡物
   建筑、大石头、大树群、特殊地貌。

3. 资源物
   树、矿、草、浆果、采集点。

4. 小型装饰物
   小草、花、碎石、落叶、地表贴花。

5. 验证与修正
   路是否通？
   出生点附近是否有基础资源？
   对象是否重叠？
   交互点是否被挡？
   地图是否有明显美术断层？
```

```text

 ↓

高度 / 湿度 / 温度 / biome 权重
 ↓
地面逻辑类型
草地 / 水 / 泥地 / 路 / 森林地表
 ↓
边缘过渡
autotile / Wang tile / transition rule
 ↓
特色地表
stamp / patch / POI ground
 ↓

 ↓

 ↓

连通性 / 资源分布 / 阻挡 / 交互空间
 ↓

Tilemap 或 mesh + decal + SpriteRenderer + Y Sort
```

## 13. Unity 落地倾向

这份文档不要求立刻实现，但如果后续进入 Unity 方案，建议方向是：

```text
地面：
- Tilemap 或自建 mesh
- 负责基础地貌和边缘过渡

贴花：
- SpriteRenderer / Tilemap overlay
- 负责自然感和局部变化

站立对象：
- Prefab + SpriteRenderer
- pivot 放在脚点
- 根据脚点 Y 排序

逻辑：
- 2D grid / chunk data
- 记录 terrain、biome、occupancy、interactable

资源配置：
- ScriptableObject 作为配置
- 但不要把 ScriptableObject 当运行时数据库
```

对象资源需要配置类似信息：

```text
ObjectDefinition
- id
- prefab
- allowedBiomes
- allowedTerrains
- footprint
- blocksMovement
- minSpacing
- density
- clusterRule
- interactionType
- placementPriority
```

地表资源需要配置类似信息：

```text
TerrainVisualDefinition
- id
- sprite / tile
- biome
- terrain
- useCase
- edgeMask
- allowedNeighbors
- forbiddenNeighbors
- weight
- rarity
```

## 14. 常见误区

```text
误区 1：让程序自动理解美术资源
修正：美术资源必须语义化，程序只能执行规则。

误区 2：把 chunk 当生成单位
修正：用全局坐标和 world seed 生成，chunk 只负责加载。

误区 3：用整张 sprite 做碰撞
修正：碰撞和占位只看 footprint。

误区 4：所有地表都靠 tile 随机
修正：基础地面低调重复，特色地表用 stamp。

误区 5：随机撒对象
修正：先算适宜度，再按规则、密度、占位和可达性放置。

误区 6：美术资源越多越好
修正：更重要的是资源语法、过渡规则和组合方式。
```

## 15. 一句话结论

```text
有特色的 2D 地形不能靠程序自动懂美术。

正确做法是：
美术定义资源语义和拼接规则；
程序生成地图意图；
规则系统把意图翻译成具体美术资源。
```

最终目标不是“随机地图”，而是：

```text
可控的随机；
有规则的变化；
可复用的美术语法；
稳定的 2D 逻辑；
可信的 2.5D 表现。
```

- 地图底层是 2D 逻辑地图
