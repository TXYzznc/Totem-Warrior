# 六人双排 PvPvE 游戏策划案（First Playable 基线）

> 文档状态：已确认设计归档  
> 归档日期：2026-08-12  
> 对应 OpenSpec：`openspec/changes/archive/2026-08-12-rebuild-six-player-pvpve-first-playable/`  
> 当前实现定位：六人、三支双人队、五轮、纯 PVP 的本地 First Playable；PVE、Enemy 与 Boss 等待后续独立设计  
> 说明：本文归档产品设计共识。精确的程序合同、数值和验收条件仍以已归档 OpenSpec 及活动主规格为准。

## 1. 改版背景

旧方案以约 20 人实时联机、多武器、多流派、PVE、Boss、撤离和大量配套内容同时成立为前提。这对“单开发者 + AI”的团队规模不现实，也难以在早期获得足够在线玩家完成匹配和测试。

旧构筑方案还存在两个核心风险：

1. 如果不同构筑只有强弱差异而缺少明确的战术差异，玩家最终会收敛到唯一最优解。
2. 如果一次性制作大量武器、流派、敌人和技能，再开始验证克制关系与操作空间，开发成本会先于玩法结论快速膨胀。

因此，项目调整为“小规模对局、单武器验证、分轮构筑、公开情报、快速形成完整闭环，再逐步迭代”的路线。

## 2. 核心产品方向

### 2.1 对局定位

- 每局固定 6 名参赛者，组成 3 支双人队。
- 玩家不足时由 Bot 补齐。
- 同队无友伤。
- 最终产品方向是带撤离目标的 PvPvE 对局；当前 First Playable 暂时只实现纯 PVP。
- 第一版不做后端、房间、好友、在线匹配和真实网络同步。

### 2.2 核心体验支柱

1. **情报驱动的构筑反制**：每轮构筑前公开上一构筑边界的全员信息，玩家根据对手的构筑和本局表现调整自己的选择。
2. **操作能够修正构筑差距**：构筑不应只比较纸面强度；命中弱点、走位、时机和团队配合应允许高手用非主流方案击败纸面更强的方案。
3. **三角克制而非唯一最优解**：设计应尽量形成类似“剪刀、石头、布”的可读克制关系，保持较低平局概率和清晰的预判博弈；但不把纹身硬性命名或分类为“突破、阵地、游击”等固定流派标签。
4. **完整结构优先于一次性打磨**：第一版首先验证一局游戏从菜单、准备、战斗、构筑、缩圈到结算能够完整运行，而不是一次制作所有最终内容。

### 2.3 构筑的设计原则

- 图案、元素、身体部位与战斗事件共同形成效果，不用预设流派标签替玩家总结答案。
- 构筑应提供可组合的规则，让流派由玩家实际搭配和对局环境自然形成。
- 公开对手信息是反制博弈的主要输入；公开的是阶段边界快照，不是构筑阶段内的实时编辑结果。
- 数值平衡之外，还必须保留操作上限、团队协作和信息判断的价值。

## 3. 版本分层

### 3.1 当前 First Playable

当前版本验证以下闭环：

- 1 名本地真人 + 5 名 Bot，组成三支双人队。
- 单一基础步枪。
- 五轮战斗、四次缩圈、五次构筑。
- P01/P02 两个临时编号图案、六个配置部位、火/冰/雷三种颜料。
- 全员构筑情报、累计成果和队友颜料请求。
- 三层元素、元素反应和按优先级结算的效果队列。
- 倒地、救援、淘汰、观战和纯 PVP 结算。
- 地图资源拾取。
- 测试版撤离解锁与本地整队撤离。
- MainMenu 到 Result 再返回 MainMenu 的完整本地流程。

### 3.2 当前明确不做

- 真实 Enemy、Enemy AI、遭遇、EnemyLoot、敌人弱点和 PVE 内容。
- Boss 战、Boss 失败结算、Boss 核心和高阶奖励争夺。
- 在线房间、好友组队、匹配、账号、后端和网络同步。
- 多武器、角色选择、玩家主动技能。
- 局外成长、商业化和正式撤离经济。
- 最终 UI、美术特效和最终枪械数值打磨。

### 3.3 后续完整 PvPvE 目标

PVE、Enemy 和 Boss 需要在后续独立策划中重新设计，不能恢复已经清理的旧方案作为占位。完整产品预期节奏为：

```text
开局构筑（60 秒）
→ 从合法出生锚点中随机生成，同队成员生成在一起
→ 第 1 轮战斗

第 2 轮构筑（45 秒）
→ 第 1 次缩圈
→ 第 2 轮战斗

第 3 轮构筑（45 秒）
→ 第 2 次缩圈
→ 第 3 轮战斗

第 4 轮构筑（45 秒）
→ 第 3 次缩圈
→ Boss 刷新
→ Boss 战、撤离点解锁、高阶资源刷新

第 5 轮构筑（45 秒）
→ 第 4 次缩圈
→ 最终高强度 PVP 与撤离
```

其中：

- 前三轮不限制 PVP，但活动区域较大，玩家更可能优先探索和发育。
- 第四轮 Boss 应具备适合多人挑战的强度。参战人数过少可能无法击败 Boss，从而出现全员无法撤离的失败风险。
- Boss 被击败后才解锁撤离点，并在地图刷新高阶奖励，推动留下的队伍继续争夺。
- 系统根据玩家对 Boss 造成的综合贡献给予局内属性强化。综合贡献可包含伤害、控制等，但算法不直接向玩家公开。
- 完成 Boss 最后一击的玩家额外获得一个特殊效果，用于增加后续博弈性。
- 希望安全撤离的队伍可在第五轮前离开；追求更高收益的队伍可以留下参加第五轮高强度 PVP。
- 第五轮缩圈后撤离点位置不再变化，但部分撤离点可能落在圈外而失效，剩余可用点更集中，撤离风险显著提高。

以上内容是后续产品方向，不属于当前 First Playable 的已实现承诺。

## 4. 当前五轮流程

权威阶段顺序为：

```text
OpeningBuild（60 秒）
→ Round1Combat
→ Build2（45 秒）
→ Shrink1
→ Round2Combat
→ Build3（45 秒）
→ Shrink2
→ Round3Combat
→ Build4（45 秒）
→ Shrink3
→ Round4Combat
→ Build5（45 秒）
→ Shrink4
→ Round5Combat
→ Result
```

- 当前第四、第五轮仍是纯 PVP，不刷新 Boss、Enemy 或高阶资源。
- 正常模式每次缩圈持续 30 秒；快速测试模式持续 10 秒。
- 构筑阶段暂停战斗世界：移动、Bot 战斗决策、伤害、元素计时、资源交互和缩圈均不推进。
- UI 倒计时使用不受战斗暂停影响的时间。
- 淘汰状态跨轮保持，不会因进入新一轮复活。
- 只剩一支存活队伍时立即结束比赛。
- 第五轮超时仍有多队时，依次比较队伍淘汰数、玩家伤害、存活人数和剩余生命；完全一致则为平局。

## 5. 六人双排与 Bot

- 本地 First Playable 固定创建 6 名参赛者：1 名真人和 5 名 Bot。
- 三支队伍互不重叠，每队两人。
- 每队从地图同类型的合法出生锚点中确定性随机抽取一个出生组；队友相邻生成，不同队不共享独占锚点。
- 同队的直接伤害、元素伤害和反应伤害均为 0，也不计入有效伤害成果。
- 敌对队伍从第一轮起即可互相伤害，前三轮不设置 PVP 保护。
- 真人与 Bot 使用同一套业务规则。Bot 不能绕过阶段、队伍、资源、伤害、构筑或交互校验。

## 6. 枪械与操作

- 第一版仅启用一款基础步枪，当前配置 ID 为 `rifle_patrol_v1`。
- 玩家和 Bot 共用瞄准、开火、命中和伤害入口。
- 玩家当前不具备主动技能。
- 玩家身体命中与头部弱点命中必须可区分。
- 枪械臂效果只在“造成有效直接伤害”后触发；命中队友、完全免伤或伤害被规则抵消时不触发。
- 所有真人按键输入必须经过项目输入服务，业务逻辑不得直接读取设备按键。
- 非人型怪物的弱点提示留待 PVE 设计，可通过 Shader 或在敌人预制体弱点处配置发光物体等方式表现。

## 7. 纹身构筑

### 7.1 图案与开放范围

- 已确认的视觉资源共有 8 个图案，但目前都没有正式名称。
- 文档、配置和 UI 使用临时编号 `P01`～`P08`，不得根据外形擅自命名为“直线”“圆环”等。
- First Playable 只开放 P01 和 P02。
- 初始玩家可使用两种基础图案。
- P03～P08 未来可通过有使用次数限制的“图案体验卡”在局内体验，但当前版本不生成、不装备。
- 图案参考资源：`artifacts/美术资源需求/通用/GEN-001_纹身贴花与遮罩/已确认/TAT-STYLE-S01_几何黑工_八图案4x2_原始.png`。

### 7.2 部位、元素和颜料

- 当前使用六个已配置身体部位。
- 每个纹身由身体部位、图案和元素共同确定。
- First Playable 开放火、冰、雷三种颜料。
- 颜料归个人持有，不与队友自动共享。
- 在地图探索和拾取过程中获得颜料。

### 7.3 修改规则与成本

- 只有 OpeningBuild、Build2～Build5 可以装备、替换或拆除纹身。
- 战斗阶段可以查看自己的构筑，但不能修改。
- 每个部位装备纹身统一消耗 10 份对应颜料。
- 拆除返还 60%，即 6 份颜料。
- 替换时先返还旧纹身的 6 份颜料，再扣除新纹身的 10 份颜料。
- 当前不区分身体部位和特殊图案的颜料成本。

### 7.4 对外效果文本

- 每个图案配置必须提供一段“不含精确数值”的公开效果文本。
- 公开文本需准确表达实际行为，但不能暴露内部倍率、概率或冷却。
- 图案的正式命名和最终效果文案仍可在后续迭代中调整。

## 8. 构筑情报与反制

### 8.1 快照时机

- 每次进入构筑阶段时，先结算仍未被救起的倒地玩家。
- 随后捕获 6 名玩家在该构筑阶段开始前的构筑与累计成果。
- 快照在本次构筑阶段内冻结；其他玩家本阶段的换装结果要到下一次构筑开始才公开。

### 8.2 当前构筑快照

每名玩家显示：

- 已装备纹身的部位、临时图案编号、元素和无数值效果文本。
- 当前属性，包括基础属性和局内强化加成。
- 基础值与局内强化值使用不同颜色文字区分。

### 8.3 本局个人成果

当前纯 PVP First Playable 显示从开局累计到快照边界的精确数据：

- 对玩家伤害、击倒、淘汰。
- 治疗队友。
- 为队友提供的护盾或减伤。
- 成功救援。
- 净化或解除控制。
- 有效控制时长或次数。
- 为队友创造的增伤收益。
- 资源获取与资源分享。
- 自身被击倒次数。

原设计中的 PVE 伤害和 PVE 击杀字段在 PVE 回归后再加入；当前纯 PVP 版本不显示空的 PVE 统计。

### 8.4 队友颜料请求

- 玩家可以选择一种颜料和数量，向唯一队友发起请求。
- 可设置的最大值是发起请求时队友持有的对应颜料数量。
- 队友同意时再次校验实际库存，并以原子事务完成转移。
- 队友拒绝、请求过期或库存已变化导致校验失败时，双方库存均不变化。

## 9. 元素系统

### 9.1 三层强度与持续时间

- 每种元素均有弱、标准、强三层。
- 重复施加相同元素时提升一层并刷新持续时间；强层再次施加只刷新持续时间。
- 每经过 3 秒自然消耗一层；弱层被消耗后元素消失。
- 构筑阶段暂停元素持续时间、伤害 tick 和层级衰减。
- 每一层元素记录来源参赛者和施加顺序，消费时遵循 FIFO。

### 9.2 元素自身特性

- **火**：灼烧每 0.5 秒结算一次，弱/标准/强使用 1/1.25/1.5 的层级系数。
- **冰**：弱/标准/强分别造成 12%/20%/28% 减速。
- **雷**：带雷目标受到有效直接伤害时，每 0.5 秒至多触发一次放电；优先命中最近的同阵营次要目标，没有次要目标时，以 50% 伤害回到目标自身。

### 9.3 元素反应

目标已有元素时再施加不同元素，会触发对应反应：新施加元素被消耗，已有元素降低一层；已有元素为弱层时，反应后直接消失。

- 火 + 冰：**热冲击**，造成 0.6 倍枪械身体命中伤害。
- 火 + 雷：**过载**，对中心造成 0.35 倍伤害，对 3 米内其他目标造成 0.25 倍伤害并产生轻击退。
- 冰 + 雷：**停滞**，使目标在 2 秒内造成的直接伤害降低 20%。
- 反应与两种元素的施加先后顺序无关。
- 不设置全局元素反应冷却。
- 当前反应是终止事件，不继续生成新的反应事件。

### 9.4 来源与成果归因

- 目标身上的每层元素保存来源。
- 如果反应完成击杀，最终淘汰归触发不同元素、使反应发生的玩家。
- 触发者和被消费元素层的来源都记录相同数值的间接元素伤害。
- 成果文本显示“间接造成 X 点元素伤害”。
- 多方成果记录不会重复扣除目标生命，实际伤害只结算一次。

## 10. 效果事件队列

同一次行为同时产生多个合法效果时，不立即嵌套结算，而是先按优先级放入队列：

| 优先级 | 事件 |
|---:|---|
| 100 | 主动技能臂（第一版玩家无主动技能，仅保留槽位） |
| 90 | 闪避 |
| 80 | 移动 |
| 70 | 头部弱点 |
| 60 | 枪械臂 |
| 50 | 躯干 |

- 优先级高的事件先结算。
- 相同优先级使用由 match seed 派生的确定性随机顺序。
- 事件逐个结算，事件之间可以加入短暂的表现延迟，让反馈更清楚。
- 表现延迟不得改变最终生命、状态、统计、随机顺序或事件合法性。
- 不设置全局反应冷却。
- 当前版本的反应为终止节点，以避免无限链和队列爆炸。

## 11. 倒地、救援、淘汰与观战

- 有可救援队友时，玩家首次受到致命伤进入倒地而非立即淘汰。
- 倒地生命为最大生命的 40%，流血时间 20 秒，移动速度为正常值的 35%，不能攻击或构筑。
- 队友需连续救援 3 秒；离开范围、救援者受控、倒地或中止交互会将进度清零。
- 救援成功后恢复 30% 最大生命、护盾为 0，并获得 1 秒保护。
- 敌人可通过伤害倒地生命完成处决；倒地生命归零或流血结束时淘汰。
- 进入任意构筑阶段前，仍处于倒地状态的玩家立即淘汰。
- 淘汰后若队友仍存活则观战队友；整队淘汰后等待本局结果，不重新生成。

## 12. 地图资源与 OasisCity

- OasisCity 是当前唯一权威玩法场景。
- 运行时不再生成旧 PCG 地形或房间。
- 场景显式配置三种互不替代的合法锚点：`PlayerSpawn`、`MapResource`、`Extraction`。
- 玩家出生、资源刷新和撤离点都只能从对应类型的合法锚点中抽取。
- 相同地图、match seed、轮次、配置和锚点集合必须得到相同结果。
- 地图资源使用独立拾取模型，不伪装成武器，也不复用 EnemyLoot。
- 每种拾取记录独立配置资源类型/ID、元素、最小数量、最大数量、权重、可出现轮次、资源键和启用状态。
- 同一种拾取物的数量在自己的小范围内确定性随机，不使用全局写死数量。
- 当前活动资源池只包含火/冰/雷颜料和明确允许的基础资源，不包含旧武器、主动技能、P03～P08 体验卡、EnemyLoot、Boss 核心或高阶撤离资源。
- 拾取物进入个人库存，队友之间仍需通过请求与批准进行转移。

## 13. 测试版撤离

测试版用人工事件验证未来“Boss 击杀后解锁撤离”的完整结构：

- 从 Round4Combat 开始，InputModule 接受一次 `Shift + Space` 解锁命令；普通空格继续用于闪避。
- 更早阶段或重复解锁会被拒绝。
- 撤离服务提供与触发来源无关的权威解锁入口；未来 Boss 被击败时直接调用同一入口。
- 解锁后按 match seed 从专用合法 `Extraction` 锚点中生成默认 3 个撤离点。
- 撤离点生成后不移动。
- 存活且未倒地的本地真人在撤离范围内持续按住 `F` 3 秒完成撤离。
- 松开按键、离开范围、倒地或受到有效伤害会中断并清零进度。
- Bot 队友倒地时不能开始整队撤离；已经淘汰的队友不阻止撤离，也不会因此复活。
- 撤离成功后，本地玩家和所有尚未淘汰的同队成员一起进入撤离状态。
- 因第一版没有后端和真实联机，本地队伍撤离成功后立即结束整局并进入 Result，不再继续模拟其他 Bot 队伍。

## 14. 主菜单与核心 UI

### 14.1 主菜单功能

First Playable 主菜单提供：

- 开始游戏。
- 纹身与元素档案。
- 玩法帮助。
- 设置。
- 制作人员。
- 退出确认。
- 版本与构建信息。
- 开发构建额外提供 seed 和快速模式入口。

当前不显示账号、好友、商店、排行榜、继续游戏、角色选择或武器选择。

### 14.2 核心流程

```text
MainMenu
→ LocalMatchConfirm
→ OpeningBuild
→ CombatHUD
→ FirstPlayableResult
→ MainMenu
```

本地对局确认需要说明 6 人、3 支双人队、Bot 补位、五轮和四次缩圈。返回主菜单时必须完整清理参与者、场景、锚点、拾取物、撤离点和对局运行状态。

### 14.3 必要界面

- MainMenu 与本地对局确认。
- 纹身与元素档案、玩法帮助、Settings、Credits 和退出确认。
- CombatHUD。
- 构筑界面与六人情报面板。
- 颜料请求、同意、拒绝和失败反馈。
- 倒地、救援、淘汰和观战反馈。
- 五轮结果与撤离结果。

最终 UI 视觉属于独立美术计划。美术未完成时，功能链路可以使用可替换占位视觉，但不能将其标记为最终视觉验收完成。

## 15. 美术资源边界

- 已完成搭建并确认风格的 OasisCity 场景继续使用。
- 当前角色采用 3D 路线，旧 2D 角色帧方案不再使用。
- 已确认的 8 个纹身图案视觉继续保留，First Playable 只接入 P01/P02。
- UI 需要按照新流程重新设计，旧 UI 资源不应作为新需求的最终方案。
- 枪械、UI 和 VFX 可在功能阶段使用稳定资源键和 fallback；最终资源由独立美术 OpenSpec 计划交付。

## 16. First Playable 验收目标

第一版的“完整”是指游戏结构可以从头到尾完整运行，而不是每个系统均达到最终品质：

- 能从 Launch 和主菜单开始本地对局。
- 能创建 6 人、3 支双人队并完成 Bot 补位。
- 能经历五次构筑、五轮战斗和四次缩圈。
- 能验证单步枪、友伤规则、弱点、纹身、元素、反应、事件队列、倒地救援、情报和颜料转移。
- 能通过纯 PVP 淘汰或测试版撤离进入 Result。
- 能从 Result 返回主菜单，并清理上一局运行状态。
- 固定 seed 下，队伍、资源、队列、归因和关键结算结果可重复。
- UI 最终美术和外部网络不作为功能闭环的前置条件。

当前 OpenSpec 已归档，任务清单均标记完成；具体自动测试、诊断和实现证据保存在对应 change 的 `baseline/` 与 `evidence/` 目录。

## 17. 后续想法库

以下内容已确认值得探索，但不进入当前 First Playable：

### 17.1 差异化颜料成本

- 当前所有部位统一消耗 10、拆除返还 6。
- 后续可让不同身体部位或特殊效果图案消耗不同数量的颜料。
- 应在 P01/P02、六部位和三元素的首轮经济节奏验证后再评估。

### 17.2 元素反应链

- 当前元素反应不会产生新事件。
- 后续可允许反应结果继续提交事件，形成可预测但具有涌现性的反应链。
- 实现前必须定义最大链深、单次事件预算、重复状态去重和归因传播，避免无限循环与队列爆炸。

### 17.3 P03～P08 图案体验卡

- 后续探索中，玩家可在局内获得具有使用次数限制的图案体验卡。
- 体验卡用于试用尚未永久开放的图案，不代表当前版本可以装备 P03～P08。

## 18. 待后续独立设计的问题

- 真正 Enemy 的职责、AI、数值、生成、弱点提示和奖励。
- PVE 在前三轮中的压力曲线与探索关系。
- Boss 的能力、多人挑战强度、失败条件和仇恨/目标规则。
- Boss 综合贡献算法、属性强化池和最后一击特殊效果。
- 高阶资源种类、价值和第五轮争夺节奏。
- 正式撤离条件、局外战利品经济和风险收益。
- 线上双人组队、Bot 补位、匹配、掉线和服务器继续结算策略。
- 单步枪最终手感、数值与长期武器扩展方案。
- 图案正式名称、完整效果池和长期平衡方法。
