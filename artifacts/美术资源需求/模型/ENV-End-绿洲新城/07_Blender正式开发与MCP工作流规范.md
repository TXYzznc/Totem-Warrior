# 绿洲新城｜Blender 正式开发与 MCP 工作流规范

> 状态：已确认。  
> 适用范围：绿洲新城全部建筑及其独立复杂装饰的 Blender 正式资产开发。  
> 目标：在不改变已确认空间结构的前提下，使 Blender 正式模型向已确认的渲染效果图看齐，并交付可安全导入 Unity 的游戏资产。

## 1. 资料职责与使用优先级

同一建筑的资料按“结构真源”和“视觉真源”分别使用，不能用单一效果图取代结构数据，也不能让白模决定最终美术外观。

| 资料 | 职责 | 使用规则 |
|---|---|---|
| 建筑详细设计案 + 楼层布局 JSON | **结构真源** | 锁定建筑包围盒、层数、标高、坐标、门窗、楼梯、可走区域、交互锚点、碰撞与净空。与其他资料冲突时优先采用。 |
| 已确认 Unity 白模及结构截图 | **结构验证** | 用于验证体块、入口、可达性、净空和正交投影；白模截图仅用于展示和复核结构，不作为最终外观参考。 |
| 已确认渲染效果图 / 五视图 | **视觉真源** | Blender 正式模型的外观目标：建筑轮廓、材料分区、装饰层次、配色、氛围与地标识别均向其看齐。 |
| 地图与风格规范、装饰目录、尺度与验收规范 | **目录级约束** | 统一城市风格、DE 装饰使用、角色尺度、通行规则和生产验收。 |
| Unity 导入约定 | **技术约束** | 统一坐标转换、命名、碰撞、LOD、材质槽、贴图与导入验证。 |

效果图若出现与详细设计案、JSON 或已确认白模不一致的新增楼层、门窗、结构或可达路径，必须记录为差异并回到结构真源处理；不得在 Blender 中直接以效果图覆盖已锁定结构。

## 2. 单栋建筑正式开发流程

```text
锁定详细设计案 / JSON / 已确认白模 / 已确认效果图
  → 在 Blender 按 JSON 建立米制结构底模
  → 用白模复核入口、通道、楼梯、净空与可达性
  → 依据效果图完成外观、材质分区和装饰层级
  → 复杂网格细节生成高模，或复杂表面细节生成贴图
  → 重拓扑、UV、Cage 烘焙、LOD 与碰撞
  → 导出 FBX 并在 Unity 中验证
```

1. Blender 使用公制，`1 Blender Unit = 1m`；建筑局部原点、正门朝向和坐标轴严格按对应 JSON。
2. 导入 Unity 时按 `Unity(X,Y,Z)=Layout(X,Z,Y)` 转换布局坐标；不得直接套用 Z-up 布局坐标。
3. 正式模型的建筑主体、门窗、楼梯、屋顶、可走面和碰撞边界由结构真源决定；效果图负责它们的最终美术呈现。
4. 每完成一个可审阅阶段，应以 Blender 截图或视图检查正、背、左、右、轴测与已确认结构/效果图的一致性。

## 3. 混元 3D 高模规则

### 3.1 用途

混元 3D 生成的内容只可作为高模来源或视觉细节参考，**不得直接作为游戏最终网格、碰撞模型或 LOD 网格**。

适用于轮廓与网格细节复杂、难以高效手工制作的独立资产，例如雕像、特殊门框、风塔冠、纹样环、器物、复杂装置或精细装饰。建筑主体仍须依据结构真源以 Blender 模块化方式搭建；不得把整栋建筑直接交给混元 3D 生成。

### 3.2 后续处理

每个混元 3D 高模必须经过以下处理后才能入库：

1. 在 Blender 中清理并确认与效果图及结构接口一致。
2. 重拓扑为可控的游戏低模；静态硬表面可使用有意布置的三角形，但最终网格不得存在 N-gon、非流形边、重复面、游离顶点或反向法线。
3. 展开 UV0 与 UV1；UV1 用于烘焙/光照且不得重叠（明确镜像设计除外）。
4. 使用 Cage 从高模烘焙法线及所需贴图，不能以不受控的 Ray Distance 替代 Cage。
5. 制作至少 `LOD0`、`LOD1`、`LOD2`，并建立简化碰撞模型。

## 4. UV 与 AI 贴图规则

当效果图的主要信息来自表面纹样、磨损、釉面、浮雕感或材质细节，而不是新增几何体时，应优先采用“低模 + UV + 贴图”的方案。

1. 先锁定低模和 UV，再调用 GPT 绘图工具生成贴图；不得先生成贴图再倒推 UV。
2. 贴图至少按资产需要交付：Base Color（漫反射）、Normal、Roughness、Metallic、AO；可按目标 Unity 材质要求打包为 ORM 或转换为对应通道布局。
3. AI 生成的 Base Color 不得包含烘焙光照、投影、镜头透视、假高光或环境遮蔽；这些信息应分别进入正确的 PBR 通道或由 Unity 光照负责。
4. Normal 必须为切线空间法线贴图，并在 Unity 中实际导入验证方向、强度和接缝；不能只凭图片外观判断正确。
5. 统一环境 Texel Density；当前建筑规范要求的独特资产与共享 Trim Sheet 分辨率、UV 间距及贴图尺寸，以各建筑详细设计案为准。

## 5. Blender MCP 的职责

Blender MCP 用于提高执行与检查效率，不替代资料真源和人工验收。

- 连接后先检查场景信息、执行最小 Python 验证、获取视口截图，再开始批量操作。
- 可用 MCP 自动搭建 JSON 对应的结构占位、创建 Collection、批量命名、放置锚点、执行重复装饰布置、调用混元 3D 生成高模来源，以及输出检查报告。
- 每次由 MCP 或 Python 改动场景前先保存 `.blend`；脚本必须围绕已锁定尺寸和坐标执行，不得自行新增结构性楼层、门洞或可达路线。
- 正式 FBX 导出后必须在 Unity 验证缩放、轴向、材质映射、法线、碰撞与 LOD；不能只依据 Blender 视口判断完成。

## 6. 交付与验收

每栋建筑至少交付：

- Blender 源文件 `.blend`，包含结构、正式网格、装饰、锚点、碰撞和 LOD 的清晰 Collection 分层；
- 高模来源及其用途记录（若使用混元 3D）；
- `LOD0` / `LOD1` / `LOD2` 模型与简化碰撞模型；
- UV0、无重叠 UV1，以及对应 PBR 贴图集；
- 导出的 FBX；
- Unity 导入验证截图/记录；
- 与详细设计案、JSON、白模及效果图的差异记录。

验收时至少确认：

- 结构尺寸、入口、门窗、楼梯、交互净空和可达路径符合详细设计案与 JSON；
- 最终视觉轮廓、材质层次、装饰与配色向已确认渲染效果图看齐；
- 对象变换已应用，导出对象 `Scale=(1,1,1)`、`Rotation=(0,0,0)`；
- UV、法线、贴图、LOD、碰撞和 Unity 导入表现均已验证；
- 不存在以效果图或 AI 生成结果私自改变已锁定结构的情况。
