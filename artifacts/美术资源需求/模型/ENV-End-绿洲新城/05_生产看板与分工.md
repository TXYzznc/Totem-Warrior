# 绿洲新城｜生产看板与分工

> 本看板遵循“先功能和尺寸真源，后白模确认，再效果图”的顺序。  
> 目标：使 Unity 白模、Blender 布局和多视角效果图始终来自同一套结构数据。

## 1. 单建筑流水线

```text
P0 功能任务卡
  → 用户确认
P1 详细设计案 + 设计图需求提示词 + 布局 JSON
  → 用户确认
P2 Unity ProBuilder 白模 + 五视角结构校验图
  → 用户确认白模
P3 独立美术代理生成五视角效果图
  → 主控结构审查 + 用户确认
P4 归档/锁版，进入下一建筑
```

`P2` 前不得生成正式效果图；`P3` 的美术代理不得修改 `P1` 的尺寸、门窗、层高、房间或白模。

## 2. 分工

| 角色 | 负责内容 | 不负责内容 | 交付物 |
|---|---|---|---|
| 主控（本对话） | 功能拆解、建筑/装饰编号、详细案、提示词、结构审查、用户确认节点、版本归档 | 不以效果图猜测尺寸 | 任务卡、详细案、JSON、审查结论。 |
| Unity 白模执行 | 依据锁定的详细案和 JSON，用 ProBuilder 搭体块、入口、楼板、楼梯、主要门窗洞；输出结构五视图 | 不增加风格细节、家具或效果图没有的结构 | `.unity`、截图、白模验收说明。 |
| 五视角美术代理（art-3d） | 依据已确认白模和提示词生成/整理正、背、左、右、轴测五视角效果图 | 不改白模，不重定义空间，不追加结构性窗门/塔楼 | 五张图、拼图、生成说明、问题清单。 |
| 结构 QA（主控复核） | 对比详细案、JSON、白模和五视图的尺寸投影、门窗、层高、入口及可见体块 | 不以审美理由改动已锁尺寸 | 验收表、差异清单、锁版结论。 |

## 3. 并行规则

1. 任何时刻只有 **1 个建筑**处于 P0–P2 的结构设计/白模阶段，避免结构标准互相漂移。
2. 某建筑白模经用户确认进入 P3 后，可启动 **1 个独立美术代理**绘制该建筑五视角；主控同时推进下一编号建筑的 P0。
3. 同一建筑的效果图生成期间，结构真源冻结；发现矛盾时只记录问题，由主控发起下一版结构变更，不能在图中私自修正。
4. 装饰遵照 `DE-01 → DE-32` 的编号顺序建立。它们不单独占用整栋建筑流水线：每完成 4–8 类装饰，制作一套可复用的 Unity/Blender 摆放样例并验收。

### 已确认的 P1 批处理例外（2026-07-28）

在 BF-03～BF-24 的 22 张 P0 功能任务卡获得集中确认后，允许按“公共/商业、生产/维护、居住”三组**并行创建 P1 前置文件**。该例外只覆盖详细设计案、布局 JSON、设计图提示词和白模制作规范；不允许并行创建真实 Unity 白模、效果图或正式模型。P2 仍须在每栋建筑的 P1 锁定后再单独进入。

## 4. 五视角美术代理的输入与输出合同

### 4.1 开工前必须提供

- 锁定版本的“详细设计案”。
- 同版本“设计图需求提示词”。
- 同版本布局 JSON。
- Unity 白模的五视角结构截图/联系表。
- 一张明确的差异禁令：不可改变的总宽深、层高、塔楼/门洞位置、楼层退台、门窗编号。

### 4.2 必须输出

| 输出 | 规则 |
|---|---|
| 正面、背面、左面、右面 | 正交感、同一比例和同一地平基线；不允许利用透视掩盖结构差异。 |
| 轴测图 | 统一从前上方观察，展示体块、屋顶、院落和入口关系。 |
| 联系表 | 五张图拼成一张总览，文件名含资产编号和版本。 |
| 生成说明 | 写明所用输入版本与已知不确定项；不确定项必须标记，不得自行发明。 |

所有建筑效果图统一使用干净的纯色/中性暖灰背景，不绘制完整街道、远景、其他建筑、角色或场景地面。地图风格与装饰目录只用于丰富建筑本体及紧邻门槛的细节：材质分层、浅马赛克、导水末端、遮阳、少量植物、货物、导管和功能接口；这些细节也必须遵守门口、通道和交互净空。
