# BF-11～BF-21 高质量白模与效果图自动验收方案

> 适用范围：`BF-11` 至 `BF-21`。  
> 目标：让 Unity 彩色白模、白模归档、五视角效果图和后续 Blender MCP 输入形成同一套可追溯真源。  
> 完成门槛：所有硬性门禁通过、总分不低于 90/100，并保存逐栋验收报告。未通过时必须修改后重新截图、重新渲染、重新验收，不设“暂时通过”。

## 1. 真源优先级与前置文件修正规则

默认优先级：

1. 已确认的用户要求与全局合同；
2. `BF-xx_详细设计案.md` 与 `BF-xx_楼层布局.json`；
3. `BF-xx_功能任务卡_P0.md`；
4. `BF-xx_白模制作规范.md`；
5. 设计图提示词与效果图。

若详细设计案与布局 JSON 冲突，不允许直接选择较容易搭建的一方。必须：

1. 列出冲突字段、两套数值和对玩法/结构的影响；
2. 以“可实际建造、可通行、尺寸闭合、符合已确认功能”为判断依据；
3. 同步修改详细设计案、布局 JSON、白模规范中的相关字段；
4. 在该建筑的 `验收/结构决策记录.md` 写明修改原因；
5. 修改后的 JSON 成为该建筑新的尺寸真源。

## 2. 每栋建筑的标准闭环

```text
读取 P0/P1/JSON/白模规范
  → Q0 真源一致性检查
  → Unity ProBuilder 彩色白模
  → Q1 几何与结构检查
  → Q2 通行与功能检查
  → Q3 四立面与轴测视觉检查
  → 不通过则修改并重拍
  → 归档白模截图
  → 生成五张独立结构锁定效果图
  → 拼接五视角联系表
  → Q4 效果图结构一致性检查
  → 不通过则定向重绘
  → 输出验收报告与 Blender 布局说明
```

## 3. 硬性门禁

以下任意一项失败，该建筑不得计为完成。

### G01 尺寸闭合

- 建筑总包围盒、楼层标高、层高、净高、墙厚、楼板厚度与尺寸真源一致。
- `Unity(X,Y,Z)=Layout(X,Z,Y)` 映射正确。
- 根对象 Scale 为 `(1,1,1)`、Rotation 为 `(0,0,0)`。

### G02 结构真实

- 所有楼板、二层体量、平台、雨棚和大型设备均有墙、柱、梁或悬挑构造支撑，不得悬浮。
- 内隔墙按设计完整连接相邻结构墙，仅在明确门洞处中断。
- 相接构件不得留出可见缝隙，不得用装饰遮盖结构错误。

### G03 门窗封闭

- 门洞两侧有墙垛，上方有同厚度、同材质的过梁或上墙段。
- 窗洞同时有窗下墙段、窗上墙段和两侧墙垛。
- 四个正交立面逐一检查，不允许墙体在门窗上方凹陷或露天。
- 彩色门窗块只表达洞口，不替代结构墙。

### G04 楼梯与竖向通行

- 楼梯级数 × 踢面高度等于层间高差，误差不超过 0.01m。
- 踏面、净宽、中间平台、起点和终点均与真源一致。
- 第一阶接地、最后一阶接平台；不得穿墙、悬空或终点错位。
- 1.1m 连续栏杆覆盖临空边；头部净空满足真源，若未规定则不低于 2.4m。
- 维护梯、装饰梯和攀爬杆不得替代正式探索楼梯。

### G05 玩家通行

- 使用 1.80m 高、0.70m 直径代理核对所有必经门、主路、次级路、楼梯和平台。
- 主通路默认不低于 1.8m，次级通路默认不低于 1.2m；具体建筑真源优先。
- 固定物、门扇、设备、管线、栏杆和交互锚点不得堵塞进入、回身或返回路线。
- 每个可探索区域均有实际可走的进入与返回路径。

### G06 功能可读

- 七类颜色与命名正确：Structure、Walkable、Function、Vertical、Entrance、Interaction、Restricted。
- 同一视角内功能区不因同色重叠而无法辨认；必要时可在不改变七类语义的前提下使用深浅变体。
- 水体、危险设备、不可走屋面和装饰平台不得误染为 Walkable。

### G07 截图证据

- 必须有 Front、Rear、Left、Right、Axon、InteriorCutaway 六张截图。
- 有关键楼梯、悬挑或复杂连接时，额外输出 `StairDetail` 或 `StructureDetail`。
- 四个正交视图使用同一投影类型和比例；轴测不得改变模型结构。
- 截图前恢复屋顶、墙体和平台激活状态，并保存 Unity 场景。

### G08 效果图结构锁定

- 五张效果图分别以对应白模视角作为结构底图或强结构参考。
- 外轮廓、层数、门窗数量与位置、楼梯朝向、平台标高、悬挑和开口关系必须与白模一致。
- 允许增加材质、灯具、格栅、浅浮雕、管线、布幔和小型异域未来细节；不得新增楼层、塔体、大门或改变建筑长宽比。
- 纯色工作室背景、日间柔光、无人物、无街景、无文字水印。
- 细节水平至少达到已确认的 BF-01/BF-06 参考：暖白石材、青绿釉面、深青铜、真实收边、门窗厚度和功能专属细节。

## 4. 评分表（100 分）

| 项目 | 分值 | 评分要点 |
|---|---:|---|
| 尺寸与真源一致 | 15 | 包围盒、楼层、洞口、固定物 |
| 结构合理性 | 20 | 承重、墙体连续、无悬浮、无缝隙 |
| 通行与功能 | 20 | 入口、返回、楼梯、净空、锚点 |
| 白模可读性 | 10 | 颜色、分区、关键结构清晰 |
| 多视角一致性 | 15 | 四立面、轴测、剖切互相对应 |
| 效果图结构锁定 | 10 | 轮廓、门窗、层数和连接一致 |
| 风格与细节质量 | 10 | 绿洲新城风格、功能身份、精细度 |

合格条件：`总分 >= 90` 且 G01～G08 全部通过。

## 6. Blender MCP 交接要求

- 布局 JSON 中每个对象必须有稳定 ID、尺寸、中心、层级、功能类别和碰撞语义。
- 文档明确哪些对象为尺寸真源、哪些效果图只提供材质与造型参考。
- Blender 搭建必须优先遵循 JSON 和详细设计案；效果图不得覆盖尺寸与位置。
- 每个固定物说明用途、允许放置面、禁放区、朝向、与通路最小距离和验收条件。

## 7. 自主迭代原则

- 发现问题立即修改，不等待统一验收。
- 结构问题优先于材质问题；多视角一致性优先于单张“好看”。
- 效果图无法稳定保持复杂结构时，先简化不影响功能的装饰轮廓，再重新渲染。
- 每次迭代只解决一组明确问题，并保留版本号与验收结论。
- 只有逐栋报告明确写出“G01～G08 全通过、总分 ≥90”时，才能进入全量完成索引。

## 8. 最终交付前的交叉审计

逐栋报告通过后，仍必须再执行一次跨真源审计，防止“报告写对、实际文件仍错”：

1. 从 JSON 按 `D* / W*` 统计每个外墙、每个楼层的门窗数量，并逐项对照四正交白模。
2. 门窗代理块可见不等于洞口有效；必须确认左右墙段没有越界覆盖洞口。重点检查每个分段墙的中心与尺寸端点。
3. 将白模五视角与效果图五视角并排制作逐栋质量对照板，逐一核对轮廓、开口、楼层、屋顶和侧向投影。
4. `InteriorCutaway / StairDetail / StructureDetail` 必须真正显示目标结构；如果被外墙或屋面遮挡，视为 G07 失败，需按剖切模式重拍。
5. 逐一加载所有 Unity 白模场景，运行 `validate_scene` 与 `validate_missing_references`；任何缺失脚本、断裂引用、重复命名错误均阻止交付。
6. 对全部 PNG 执行解码检查，确认宽高有效、文件非空；联系表不能替代独立视图。
7. 最终审计发现的问题必须回写结构决策记录与逐栋验收报告，并覆盖旧截图或旧效果图，禁止只在汇总文档中备注。
