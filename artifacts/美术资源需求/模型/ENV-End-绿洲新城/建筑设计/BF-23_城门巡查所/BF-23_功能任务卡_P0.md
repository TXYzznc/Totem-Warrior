# BF-23 城门巡查所｜P0 功能任务卡

> 阶段：P0 功能定义；尚未锁定尺寸、平面、白模、世界坐标或效果图。  
> 建筑编号：`BF-23`；实例配额：2；建议分区：城门/台基相邻的人行入城侧，两座实例可分别作为进城与出城侧原型变体。

## 1. 建筑身份与层级限制

城门巡查所承担入口问询、秩序提示与城市导向。它应与城门/台基形成一个可探索的服务节点，但不是城门本体，更不能变成压倒城市的军事堡垒。

- 建筑身份来自问询窗口、巡查桌、台基观察廊和导向标识，而非高墙、箭塔、封闭哨楼或巨型徽章。
- 入口防卫以清晰分流和可见巡查面表达；玩家通行不应被排队栏、桌台或装饰困住。
- 两座实例共享“问询前室—巡查室—可走观察廊—回到城门人行线”的功能；P1 可镜像朝向，不确定最终城门位置。

## 2. 玩法功能

| 项目 | 规则 |
|---|---|
| 城市导向 | 玩家从入城/出城人行线进入，能在室内读取城市方向、巡查信息和下一步路线。 |
| 可交互点 | 预留问询台或城市导向板锚点；前方保持交互净空，不能与排队或城门人流冲突。 |
| 探索 | 提供问询前室、巡查/记录室与可走台基观察廊，避免只做一扇检票窗口。 |
| 事件边界 | 不绑定三选一事件、随机商人或 Boss；可留 `DE-32` 作为通用说明点，不专属化。 |

## 3. 最小可探索室内与竖向结构

| 区域编号 | 区域 | 功能 | 空间要点 |
|---|---|---|---|
| F1-01 | 问询前室 | 进站、城市导向、排队缓冲 | 与城门人行线相接但不占城门主通道；桌台后方留工作人员通路。 |
| F1-02 | 巡查/记录室 | 记录、短交互、环境叙事 | 从前室可达，能看到通向台基的楼梯提示。 |
| F1-03 | 城门侧通道 | 室内外过渡、观察窗 | 不得把它做成唯一狭窄瓶颈；须有明确回到前室的路。 |
| F2-01 | 台基观察廊 | 观察城门人流、导向、回望 | 是正式可走平台，边缘必须有连续栏杆；不以封闭装饰塔替代。 |

F1 至 F2 使用正式楼梯：后续 P1 锁定均匀踏步、足够净宽、转向平台、最小 2.4m 头部净空及 1.1m 栏杆。观察廊必须可通过原楼梯回到前室，并可接回城门人行侧；城墙垛口、攀爬梯、旗杆梯和仅供维护的外梯均不算探索路线。

## 4. 玩家流线

```text
城门人行入城侧 / 出城侧
  → 问询前室（F1-01）
  → 问询台或导向交互
  → 巡查/记录室（F1-02）
  → 城门侧通道（F1-03）
  → 正式楼梯 → 台基观察廊（F2-01）
  → 原楼梯返回前室
  → 回接城门人行线
```

巡查建筑只能与城门人流并行，不得强制玩家绕进室内才能穿城。玩家可以进入、问询、观察、返回；无论城门外侧还是内侧均有明确离开路径。

## 5. 外部接街与 DE 约束

- 接城门/台基相邻的人行入城侧或出城侧；不确定最终城市坐标、道路轴线或城门左右关系。
- 可使用 `DE-02/03/12/13/18/19/23/27/32`。`DE-03` 台阶边界须清晰，`DE-12` 同一立面不超过两面且不遮入口。
- 不用 `DE-22/25/31` 在城门主通道、排队净空、楼梯口或观察廊出口堆放；门前只采用克制的导向组合。

## 6. P0 验收条件

- [ ] 两座 `BF-23` 均明确是城门服务/巡查节点，而非城门本体、堡垒或普通商铺。
- [ ] 玩家可在不阻断城门主通行的情况下进入问询、阅读记录、经正式楼梯登上观察廊并返回。
- [ ] 观察廊的楼梯、平台、栏杆、头部净空和回接人行线均作为后续硬约束；维护/攀爬梯不计探索。
- [ ] 问询交互区、排队缓冲与城门人行线职责清楚，装饰不形成通行瓶颈。
- [ ] 未写入最终城市世界坐标，也不绑定商人、三选一事件或 Boss。

## 7. 确认后进入 P1 的工作

输出共享原型及进/出城变体的台基关系、门窗/楼梯/观察廊、交互锚点、固定 `DE` 坐标、布局 JSON 与设计图提示词。其后的 P2 白模必须以多色方块区分结构、城门人行净空、问询区、工作人员区、楼梯、可走平台和栏杆，验证室内与台基均可探索。
