# BF-20 巷道窄面住宅｜P0 功能任务卡

> 阶段：P0 功能定义；本卡不锁定尺寸、平面、局部坐标、白模或效果图。  
> 建筑编号：`BF-20`；实例配额：6 座可进入实例；建议分区：E. 工坊与居住坡巷（接狭窄次级巷、短门洞与内向采光庭）。

## 1. 建筑身份与层级限制

这是门面窄、室内纵深发展的居住单元。它用前后房、门洞序列和小型采光庭化解狭长感，表达高密度但仍宜居的坡巷生活，而不是只能从巷道看到的一张立面。

- 巷侧只保留一处克制窄门面和必要采光/导风口；内部必须沿纵深展开为可走房间序列，不做一眼望到底的空盒子。
- 默认以可探索首层为主；可设置二层或屋顶，但只有具备完整楼梯和返回路径时才计入探索，不以外观层数充数。
- 不设商业柜台、店招、作业台或公共接待区，避免与 BF-21、小型商人店或工坊混淆。

## 2. 玩法功能

| 项目 | 规则 |
|---|---|
| 纵深探索 | 玩家从巷侧门穿过前室、采光庭/天井与后室，逐步发现居住信息，而不是只在门口观察。 |
| 空间导向 | 门洞、光井、材料变化或低亮导向灯构成室内 breadcrumb；不得依靠 HUD 指示。 |
| 轻叙事 | 每个实例至少 1 个环境叙事/轻交互候选点，放在前室、采光庭或后室之一。 |
| 居住边界 | 不绑定商人、纹身师、Boss 与三选一事件；外部巷口可另做通用事件候选空间。 |

## 3. 最小可探索室内

| 区域编号 | 区域 | 功能与可达要求 |
|---|---|---|
| F20-01 | 巷侧前室 | 从窄门面进入；允许收纳或会客信息，但不能堵住主线。 |
| F20-02 | 中段采光庭/天井 | 实际可踏入或绕行的采光节点，打断狭长感并组织视线。 |
| F20-03 | 后部起居/休息室 | 至少一处完整可走的居住核心。 |
| F20-04 | 私密或服务房 | 至少一间可进入的卧室、洗护/储物间或学习角。 |
| F20-05 | 竖向到达区（如采用） | 只有在建二层/屋顶时设置；必须是实际楼梯和平台。 |

## 4. 玩家流线与竖向规则

```text
窄巷
  → 前室（F20-01）
  → 采光庭/天井（F20-02）
  → 后部起居（F20-03）
  → 私密/服务房（F20-04）
  → 原路经采光庭返回窄巷
```

- 首层主流线必须连续、可回转，不能被储物、屏风或门扇切断；采光庭不可用作无法穿越的纯视觉井后仍声称其可探索。
- 二层/屋顶：可选。采用时，F20-05 必须从首层主流线安全接入，使用真实住宅楼梯和中间/到达平台；可达层至少包含可走房间或可走屋顶停留面，并有原路或另一条合规路径返回地面。
- 所有楼梯、平台、开口和屋顶边缘在 P1 按《04》确认踏步、头部净空与 1.1m 栏杆；假门、假梯、封闭夹层和不可到达装饰层不得纳入探索计数。

## 5. 接巷与外部净空

- 接狭窄次级巷，主门保持清楚可见且门前不堆放 DE-20、DE-22 或摊位；不写最终巷道宽度、朝向、世界坐标或相邻建筑编号。
- 窄门面可采用高侧窗、短帘或门牌建立身份，但必须保留室内采光/通风解释；不靠大面积玻璃或霓虹店招解决可读性。
- 后部可面向内部小庭或维护缝作为通风/服务面，但不把它假定为第二出口；正常返回依然可经主门完成。

## 6. 允许实例变体

- 可变：前室/后室功能对调、采光庭在中段偏左或偏右、门洞序列、天井开口、可选二层/屋顶的采用与楼梯位置。
- 不可变：窄门面、纵深空间序列、真实采光庭/天井节点、至少一处后部生活空间与可回返街巷的连续路线。
- 6 座实例须轮换天井尺度感、门洞节奏、生活叙事和立面遮阳，避免连续巷道成为复制粘贴的“同一条管道”。

## 7. P0 验收条件

- [ ] `BF-20` 具备窄门面与可探索纵深室内，不是封闭门头或单一长条盒子。
- [ ] 前室、采光庭/天井、后部起居和私密/服务空间形成可走、可返回的真实流线。
- [ ] 任何采用的二层/屋顶均由安全楼梯、平台、栏杆与返回路径支撑；不可达构件未计入探索。
- [ ] 门洞、主通道、采光庭环路和楼梯无家具、货物、绿植或门扇冲突。
- [ ] 6 座实例差异可读，且不侵入 BF-21 的住店功能边界。

## 8. 确认后进入 P1 的工作

输出纵深平面、采光庭/天井开口、门洞和通道数值、可选竖向层可达声明、楼梯/栏杆、叙事锚点、接巷净空、实例变体矩阵、布局 JSON 和设计图需求提示词；P2 用多种颜色方块区分前室、采光庭、后部生活区、可行走通道、楼梯与任何不可探索夹层。
