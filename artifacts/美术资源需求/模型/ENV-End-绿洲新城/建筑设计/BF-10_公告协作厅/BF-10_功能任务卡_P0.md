# BF-10 公告协作厅｜P0 功能任务卡

> 阶段：P0（功能定义，待确认）；本卡不锁定尺寸、公告内容、任务系统、平面、白模、效果图或城市世界坐标。
>
> 建筑编号：`BF-10`；实例配额：1 座可进入实例；建议分区：水庭公共区（正门面向公共广场/公共停留面）。

## 1. 身份与层级限制

公告协作厅是公告、任务、社区信息与协作服务的公共入口。它需要比档案馆更开放、比商店更公共，但仍应是可日常使用的中尺度建筑，不是城市主地标、城门或 Boss 建筑。

- 正门必须面向公共广场/公共停留面，建立可读的公共门厅；本卡不锁定广场坐标、方位和最终相邻建筑。
- 公告/协作是功能容器，不在 P0 绑定任何具体任务、三选一事件、NPC、联网规则或 UI。
- 本 P0 采用单层公共厅与协作侧室，优先确保高频人流可绕行；禁止以巨型台阶、塔楼、强发光幕墙或 BF-01/BF-06 级仪式体量制造伪地标。

## 2. 玩法功能

| 项目 | P0 规则 |
|---|---|
| 公告入口 | 玩家进门后可识别公告读取区/任务锚点所在方向。 |
| 协作服务 | 预留多人/社区协作信息或服务的空间位置，不定义具体技术实现。 |
| 公共停留 | 提供短停、查看和与其他流线错开的等待边，不能堵主进出。 |
| 可选探索 | 协作侧室或信息整理边可独立进入，并形成回到公共厅的短环。 |
| 通行组织 | 高频交互位、门厅、侧室和后勤/服务出口必须互不抢占。 |

## 3. 最小可探索空间

| 区域 | 必须承载的功能 | P0 空间要求 |
|---|---|---|
| 广场侧门廊 | 从公共广场抵达、识别入口 | 入口朝向公共广场/停留面，门廊不挤占广场主要行走带。 |
| 公共门厅 | 分流、方向确认、短停 | 进门可同时读到公告区和协作侧室方向。 |
| 公告/任务信息区 | 读取、交互锚点 | 面向公共门厅，交互排队/停留不堵住进出门。 |
| 协作侧室 | 深度信息、协作服务、可选探索 | 有实际出入口，可回到公共门厅，不是玻璃盒背景。 |
| 后部信息整理/服务边 | 后勤、第二离开 | 与公共区有可通行连接，接后侧服务面。 |

## 4. 玩家流线

```text
公共广场/停留面 → 广场侧门廊 → 公共门厅 → 公告/任务信息区
                                         ├→ 协作侧室 → 回公共门厅
                                         └→ 后部整理/服务边 → 服务出口 → 外部服务面
```

- 玩家可直接抵达公告交互，也可绕入协作侧室探索后回到门厅；公告交互未使用时，公共厅仍可穿行和读取环境。
- 正门原路返回是基础路径；服务出口提供第二离开路径，二者都不得被公告板、座椅、排队位、门扇或装饰侵占。
- 本类型为单层：禁止用高台公告墙、不可用夹层、装饰梯、跳跃或传送模拟二层探索；若 P1 需要加层，须设置实际可走公共楼梯、每层到正门/服务出口的返回路径，并禁止以单向落差作为唯一出口。

## 5. 外部接街与净空

- 正门接水庭公共区的公共广场或公共停留面，服务出口接后侧服务边；不为原型写入世界坐标、轴线或广场尺寸。
- 广场侧门廊需保留进出、停步、读取公告入口和绕过等待人群的连续净空，公告装置不得外溢至主步行面。
- 服务出口保持可用，但不与正门形成互相冲突的穿越流或将后勤堆料暴露到公告入口。

## 6. P0 验收条件

- [ ] `BF-10` 为 1 座可进入公告协作厅，正门面向公共广场/公共停留面。
- [ ] 公共门厅、公告信息区、协作侧室和后部服务边均为可转化的实走空间。
- [ ] 公告交互、等候、入口/出口、侧室探索和服务流线互不堵塞，且有两种返回室外方式。
- [ ] 未绑定具体任务/事件/UI/联网实现，不与 BF-09 档案馆或 BF-06 Boss 功能混淆。
- [ ] 单层无伪楼层；未来加层的真实楼梯与返回约束已明确；未编造城市坐标。
