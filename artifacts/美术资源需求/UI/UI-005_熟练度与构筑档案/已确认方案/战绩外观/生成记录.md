## 生成与处理流程

1. 使用内置 `image_gen` 生成两张 L2 网格绿幕源：`战绩外观_绿幕源_01.png`（4×4，16 单元）和 `战绩外观_绿幕源_02.png`（2×2，4 单元）。提示词强制：全画布背景 `#00ff00`、无文字、无场景、组件之间至少 48px / 96px 绿色留白、主体不含纯绿色。
2. 执行 `python 规范绿幕.py`，将生成器造成的近绿色背景统一为精确 `#00ff00`，不改变非绿色主体。
3. 对整张画布先去绿：

```powershell
.venv/Scripts/python.exe tools/chroma_key_tool/chroma_key.py "战绩外观_绿幕源_01.png" "战绩外观_绿幕源_02.png" -o "去绿合并图" --key "#00ff00" --threshold 80 --soft-edge 30 --despill 0.5 --json --overwrite
```

4. 再调用切图工具：

```powershell
.venv/Scripts/python.exe tools/ImageCut_Tool/image_cut.py "去绿合并图/战绩外观_绿幕源_01.png" -o "切图暂存/批次01" --alpha 16 --min-area 80 --padding 2 --json --debug --overwrite
.venv/Scripts/python.exe tools/ImageCut_Tool/image_cut.py "去绿合并图/战绩外观_绿幕源_02.png" -o "切图暂存/批次02" --alpha 16 --min-area 80 --padding 2 --json --debug --overwrite
```

5. 执行 `python 整理组件.py`。该脚本只对上述**去绿后的生成网格**按预定义单元提取并紧裁透明边距，输出本记录的 20 个语义化 PNG；没有从原 UI mockup 裁任何矩形。
6. 执行 `python 验证.py`。

## 验证结果

- 两张绿幕源均为 `1254×1254` RGBA；四边所有像素都是精确 `#00ff00`。纯绿像素计数分别为 `1,037,037 / 1,572,516` 与 `1,136,836 / 1,572,516`。
- 已通过目视审查两张源画布：所有主体均为蓝灰、暖白、青色或珊瑚色，没有纯绿色主体；环形空洞中的绿色属于可去除背景。
- 20/20 最终组件均通过：PNG、`RGBA`、文件大于 1KB、四角 alpha 全为 0、含 alpha < 40 的透明像素、前景纯绿色像素为 0。
- 最终组件文件大小范围为 29,399–296,329 bytes。

## 瑕疵与处理

- `image_cut_tool` 对批次 01 的点绘、波浪及装饰性莲花等断开线稿会识别为额外的独立小连通域（30 个），这属于连通域切图的正常限制。已保留完整原始切图输出和 debug 图；最终组件从同一张去绿网格按已验证的 4×4 单元进行语义化整理，避免把一个徽章拆成无用碎片。
- 未观察到明显绿边；若后续在深色背景上发现细微边缘残绿，可提高 `--despill` 后仅重跑对应批次。
