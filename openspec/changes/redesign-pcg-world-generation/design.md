## Context

当前运行时以 `PCGThemeMapLayout` 的固定模板构造 64×64 地形：每张主题地图的水域、补丁和房间中心由少量硬编码形状组成，种子只改变有限的扰动。`TotemMapService` 再把这份地形结果同时用于渲染、通行判断、固定锚点和可视物投放。现有锚点是固定 ID、固定房间中心附近的位置，不能表达一局地图中多处出生、商人、宝箱或事件随种子分布的需求。

美术资源已完成三张地图的导入（每主题 31 项，另有 8 项通用资源），并已通过 `WorldObjectCatalog` 提供按地形投放的静态物件与锚点视觉壳。它们可直接复用，但当前按精确锚点 ID 查找视觉壳的方式不适合一类事件出现多次。

本设计将地图视为一份由种子确定性生成的“世界计划”（World Plan），而非同时承担所有玩法逻辑的 Tilemap。世界计划拆分为宏观地貌格网与微观世界坐标两种尺度；渲染、事件、碰撞和交互分别消费所需层。当前版本的唯一启用能力是视觉，所有坐标均可通行；未来能力在同一数据契约上按主题配置启用。

相关干系人包括关卡/玩法设计、美术、客户端运行时和后续交互系统。运行时仍须兼容 Unity 2022.3.62f3、现有 `TotemMapAnchor` 消费者和当前的资源目录加载路径。

## Goals / Non-Goals

**Goals:**

- 以通用、配置驱动的分层生成器替代主题专用的固定形状代码；同一种子和配置必须产生相同世界计划。
- 定义三主题共十二种地貌的空间叙事、宏观形态、视觉资源亲和性及未来能力画像；水域只是可变形地貌之一。
- 通过宏观地貌格网生成面积、形状、邻接和密度，通过微观坐标生成事件、地标和立物。
- 将出生、Boss、商人、纹身师、宝箱等统一为事件层中的可配额锚点；同类锚点可多次出现且随种子变化。
- 建立可叠加的视觉、碰撞、移动修正、遮挡、危险、交互和事件亲和性能力模型；当前明确关闭除视觉外的所有能力。
- 迁移现有美术目录，使 101 项已导入环境资源可以按主题、地貌、区域和事件角色投放。
- 删除未接入且已废弃的 BSP、区域规则目录、边缘匹配、过渡遮罩和水边底图路径。

**Non-Goals:**

- 本变更不定义具体敌人、商人、宝箱或事件的玩法效果、数值、网络同步和掉落。
- 本变更不在当前版本启用碰撞、减速、伤害、遮挡或任何通行限制，也不以可达性验证作为地图准入条件。
- 本变更不要求把宏观地貌变成真实 Unity Terrain 高度图；当前仍可使用现有 Tilemap/精灵渲染实现。
- 本变更不承诺为每种地貌新增美术资源；优先组合已导入资源，缺口由后续美术迭代填补。

## Decisions

### 1. 用 World Plan 作为单次生成的唯一数据产物

生成入口接收 `themeId`、`seed`、地图尺寸及对应配置，输出不可变的 `PCGWorldPlan`。该计划至少包含：宏观地貌单元、区域/密度场、保留区、事件锚点、视觉投放请求、能力标签和可复现元数据。渲染器、事件系统和未来碰撞系统各自从计划读取数据，不能通过读取 Tilemap 反推规则。

选择它而不是让 `TotemMapService` 继续同时生成并持有一切状态，是为了把纯视觉版本和将来的玩法版本隔离；同一世界计划可被预览、哈希、测试和重放。

替代方案是继续扩展 `PCGThemeMapLayout`。未采用，因为它会把主题差异、锚点和游戏规则继续耦合进一个固定模板类。

### 2. 采用“双尺度”空间，而不是只提高格网分辨率

宏观格网（当前可保持 64×64，配置允许调整）表达地貌 ID、区域归属、密度、特征归属和能力标签。微观空间以世界坐标表达事件锚点、地标、立物、未来碰撞轮廓和交互区域；它通过宏观单元的候选采样、最小距离和保留区约束确定。

选择它而不是把事件也锁在单格中心，是因为出生点、宝箱和角色视觉尺寸远小于地貌单元，且同一地貌单元可以容纳多个独立事件候选。宏观层保持构图稳定，微观层提供事件丰富度。

### 3. 用通用特征配方组合地貌，不在生成器中写主题分支

每张地图由若干 `TerrainFeatureRecipe` 组成。配方使用统一操作：基底场、Blob（湖泊/岛屿/菌毯）、Ribbon（弯曲河道/冷却液沟）、Chain（串联腔室/沼泽洼地）、Scatter（斑块/孢子点）和 Fringe（邻接边缘）。每个操作均接受数量、面积预算、尺度、曲率、噪声、位置偏好、邻接偏好、间距和覆盖优先级等确定性参数。

水域配置可同时包含湖、塘、湿地斑块与一至多段弯曲水道；不再由“单条竖线水道”规则生成。其他地貌同样以面积和形态预算生成，因此丰富度来自组合与约束，而不是只有水域随机化。

选择配方系统而不是纯 Perlin/Value Noise 阈值，是因为纯噪声难以保证可读的地貌叙事、面积下限和美术投放结构；配方仍可在各操作内部使用平滑哈希噪声产生自然边界。

### 4. 地貌先形成主题画像，再决定算法参数

所有主题共享四个地貌槽位，但其空间意义和未来能力由配置定义：

| 主题 | 地貌 | 空间与视觉特征 | 未来能力画像（当前不启用） |
| --- | --- | --- | --- |
| AI 遗迹 | ruins_floor | 主广场、通行甲板、开阔基底 | 事件枢纽、默认视觉层 |
| AI 遗迹 | ruins_metal | 机械服务带、破损金属岛与设备群 | 遮挡/碰撞候选、掩体亲和 |
| AI 遗迹 | ruins_growth | 被生物侵蚀的机库、团簇蔓生区 | 遮挡、采集/危险候选 |
| AI 遗迹 | ruins_coolant | 冷却池、沟槽与泄露洼地 | 减速/电气危险候选 |
| 异形巢穴 | hive_chitin | 甲壳骨架、脊状支撑带 | 碰撞/遮挡候选 |
| 异形巢穴 | hive_membrane | 膜状孵化区、软组织铺层 | 减速、能见度变化候选 |
| 异形巢穴 | hive_resin | 树脂腔、桥状凝结区与巢室群 | 掩体、事件亲和候选 |
| 异形巢穴 | hive_acid | 酸液池、渗流带与小型积液 | 减速/危险/交互候选 |

生成器只识别地貌 ID 和配方；表中差异全部落到主题配置。这样后续增加第四张地图不需要向核心生成流程添加 `if (theme == ...)`。

### 5. 事件层以“类型 + 预算 + 亲和性”布局，废除固定房间中心锚点

`EventLayoutProfile` 为每类事件定义最小/最大数量、最小距离、彼此排斥或成组规则、地貌/区域亲和性、距边缘范围、可视壳角色和可选保留区。布局器先在符合亲和性的宏观单元中生成微观候选，再用确定性加权采样和最小距离剔除完成配额。

当前配置至少支持：有效玩家出生候选 ≥10、Boss ≥1、商人 ≥3、纹身师 ≥5、宝箱 ≥30。玩家从同一局世界计划中全部有效的出生候选内随机选择；选择过程不重建地图。其余事件类别不在架构中写死，均可由配置新增。

事件锚点 ID 采用稳定的语义序号，如 `player.spawn.000`、`chest.012`，而不是固定的单例 ID。过渡期间由适配层向仍依赖旧单例键的消费者提供其指定类型的主锚点；消费者随后迁移到按事件类型查询集合。

### 6. 能力层是数据，不是当前地貌的实际效果

每种地貌和元素都可携带 `CapabilitySet`：`Visual`、`Collision`、`MovementModifier`、`Occlusion`、`Hazard`、`Interaction`、`EventAffinity`。能力数据包含启用状态、标签和参数引用，但不直接包含具体效果脚本。运行时由能力消费系统在主题配置显式启用时注册碰撞体、效果区域或交互对象。

当前 `CapabilityActivationProfile` 仅启用 `Visual`，并要求所有宏观单元和微观事件位置都报告为可通行。这样“水域视觉”不会意外继承旧的阻挡行为；将来启用碰撞时，也不需要重新设计世界数据结构。

替代方案是在未来为每张地图写独立的 `SwampWaterEffect` 等组件。未采用，因为会使主题增多时的行为组合失控，且与用户要求的配置驱动相冲突。

### 7. 视觉资源按语义角色匹配，保持资源目录与生成职责分离

`WorldObjectCatalog` 继续保存资源路径、主题、地貌标签和投放权重。锚点视觉壳从“精确 anchorId → 资源”迁移为“主题 + eventType/visualRole → 候选资源”，以支持同类事件多次出现。视觉投放器在 World Plan 的密度场、地貌、保留区和事件净空区上采样，形成实例请求；渲染器使用现有预算和池化策略实现这些请求。

生成配置不保存 Unity 资源路径；资源目录也不保存算法形状参数。这避免美术替换导致地图算法配置改动，反之亦然。

### 8. 生成顺序与确定性

固定顺序为：请求归一化 → 基底/保留区 → 地貌特征配方 → 区域与密度场 → 事件候选与配额布局 → 视觉投放 → 能力标签汇总 → 结果哈希与快照。每一步从主种子派生具名子种子，禁止依赖 Unity 全局随机数或枚举顺序。任一步新增随机消耗不得改变其他阶段的随机流。

计划在地图加载时生成；不得在 `Update` 中分配集合或重算布局。地貌格网使用预分配数组，视觉实例沿用预算、批次和对象池。

### 9. BSP 仅作为历史数据表兼容字段，不得再进入 PCG

`MapTemplateConfig` 仍保留 `BspMaxDepth` 列及自动生成的通用读取器，以避免在本次 PCG 变更中同时破坏既有数据表二进制/代码生成协议；但 `TotemMapTemplateDefinition`、`TotemMapSnapshot`、`TotemMapService` 的运行时设置、缓存键、`PCGMapGenerateRequest` 与生成器均已不再接收或读取它。它因此不能影响主题、地貌、事件、锚点或视觉结果。

未来若要从数据表彻底删除该列，应在数据表 schema、代码生成输入、二进制表重建和游戏目录构建脚本中作为一次独立迁移执行；不得通过手改生成的 `MapTemplateConfig.cs` 删除字段。

## Risks / Trade-offs

- [配置自由度过大，设计师容易组合出不可读地图] → 提供主题预设、面积/数量硬约束、编辑器预览、种子库和构图检查清单。
- [事件配额与最小距离在小地图上相互冲突] → 布局器按优先级降级可选数量；对“最小数量”失败输出含原因的生成诊断，而非静默少生成。
- [全图可通行掩盖未来碰撞带来的可达性问题] → 当前不执行准入验证；能力启用版本单独引入可达性验证阶段和迁移验收，不倒灌到纯视觉版本。
- [锚点 ID 迁移影响既有服务] → 先实现单例兼容适配和消费侧审计，再删除旧键约定；以固定种子回归测试事件消费。
- [多层特征与大量立物增加加载成本] → 限制宏观格网大小、特征预算与对象预算；使用确定性候选采样而非无界重试；以加载耗时和实例数作性能门槛。
- [资源目录文档与实际导入状态不同步] → 把资源存在性和目录标签检查加入 PCG 验证命令，文档仅作交接说明而非运行时真相。

## Migration Plan

1. 新增纯 C# 的 World Plan、配置 DTO、配方执行器和确定性测试，不改变现有地图渲染。
2. 为三主题录入地貌、特征、能力激活和事件布局配置，并把现有 101 项资源目录迁移到语义角色索引。
3. 让 `PCGMapGenerator` 生成 World Plan；由适配器继续向现有 `TotemMapService`、Tilemap 渲染和 `TotemMapAnchor` 消费者提供兼容数据。
4. 将固定锚点消费者迁移为按事件类型读取锚点集合；保留主锚点适配直到全部消费者完成迁移。
5. 删除 `BspMaxDepth`、`ZoneRuleCatalog` 及其资源、固定形状模板、边缘匹配/过渡遮罩/水边底图死路径和与它们对应的测试。
6. 执行 30 种子/主题的自动快照与资源检查，并为每主题人工审阅 3 个种子；通过后切换默认生成器。

回滚策略：保留旧生成器一个发布周期，并由启动配置选择旧/新适配器；新 World Plan 配置或资源校验失败时回退旧生成器并记录种子和失败原因。删除旧实现仅在兼容消费者和回归验证全部完成后进行。

## Open Questions

- 未来碰撞启用后，是否由宏观单元直接生成碰撞，还是由独立的微观碰撞轮廓资产覆盖？本变更保留两种数据入口，暂不决定。
- 世界事件是否需要服务端权威种子与锚点同步？当前仅定义本地确定性数据契约，不定义网络协议。
- 运行时主题配置最终采用 ScriptableObject、JSON 还是 DataTable？本变更要求“可数据驱动且可版本化”，具体作者工具在实现前结合现有项目数据管线确认。
