## Context

UI-001、UI-002、UI-004 与 UI-005 的确认效果图是视觉和信息层级参考，不是可直接裁切的贴图来源。上一轮按画面对象切图，混入角色、纹身、物品和材质预览，且没有以交互状态和跨页复用为边界。

本变更只处理 UI 美术资产规划与生产。UI-002 固定使用 `UI-002_颜料失序_纹身工作台_主界面_C_v2.png`；该版本由用户明确认可。目标平台为 Unity 2022.3 的 UGUI，所有文本由 TMP_Text 渲染，所有按键提示在实现阶段通过 InputModule 注入。

## Goals / Non-Goals

**Goals:**

- 对每张效果图先建立节点树、运行时槽位和状态表，再确定需要生成的贴图。
- 将九宫格边框、选择框、卡片壳、锁定遮罩、进度轨道和按键提示底板等稳定形状归入通用 UI 组件库。
- 对每个页面生成其专属壳体和未在效果图中表现、但实现完整状态机所需的美术资源。
- 为每个 PNG 记录用途、来源、状态、切片方式和 Unity 使用方式，并完成透明像素验收。

**Non-Goals:**

- 不生成角色模型、角色肖像、纹身图案内容、物品图标、皮肤/材质预览或数字/普通文字；它们是数据驱动展示内容。
- 不创建 Prefab、不写 UGUI 代码、不修改 InputModule 或既有效果图。
- 不删除上轮生成物；它们只作审计参考，不作为新版实现来源。

## Decisions

### 1. 按运行时职责而非画面外观分类

每个效果图节点必须标记为 `ui-shell`、`runtime-slot`、`data-asset` 或 `text`：

- `ui-shell` 生成或复用 Sprite；可交互节点同时声明状态。
- `runtime-slot` 只定义容器、遮罩、边框和比例规则，运行时加载资源。
- `data-asset` 由物品、纹身、角色或构筑数据提供，不放入页面 UI 素材目录。
- `text` 由 TMP_Text 和本地化数据提供。

这比“效果图中看得见就生成”的方式更贴合 UGUI 的组合方式，也避免角色和贴花被烘焙进 UI。

备选方案是继续按视觉区域整块切图；该方案无法处理动态内容、状态切换和分辨率适配，故不采用。

### 2. 以可变形规则决定通用组件归属

满足“形状一致、仅色彩变化或可由九宫格/拉伸复现”的壳体，一律放入 `artifacts/美术资源需求/通用UI组件/`；页面目录只保留不能由通用组件表达的语义性装饰和专属遮罩。

通用目录按 `面板`、`选择`、`卡片`、`进度`、`状态`、`输入提示` 分组。颜色由 Unity Image.color、材质参数或局部覆盖层处理，禁止为同形不同色重复生成 PNG。

备选方案是每页自行保留副本；该方式会造成风格漂移、资源冗余和不可控的修订成本，故不采用。

### 3. 状态以功能状态机为来源，不以单张效果图可见状态为上限

每个交互组件最低声明 normal、focused、pressed 和 disabled；存在权限条件的卡片增加 locked；存在异步提交的页面增加 loading、success 与 failure。若状态仅为色彩变化，沿用同一形状 Sprite 并在 Unity 侧 tint；只有轮廓、填充或材质变化才生成额外 Sprite。

备选方案是只生成效果图中可见的一态；该方案会使按钮和卡片在交互中缺少反馈，故不采用。

### 4. 新版目录与旧审计目录隔离

新版产物写入每张效果图下的 `结构重制` 目录，通用资产写入 `通用UI组件`；每个目录包含 `素材清单.md`、绿幕源、去绿合并图、最终 PNG、验证结果和生成记录。上一轮目录不移动、不删除。

备选方案是直接覆盖旧文件；这会丢失错误复盘证据，并可能破坏已有引用，故不采用。

### 5. 生成与验证链路保持可追溯

带边框、高光或纹理的壳体采用纯 `#00ff00` 绿幕生成，整图去绿后再切分；纯色几何件可程序化生成透明 PNG。最终组件必须通过 RGBA、四角 alpha 为 0、存在透明像素、文件可打开和语义清单逐项核对。

备选方案是从效果图裁切矩形；这会把面板底色带入组件，故明确禁止。

### 6. 用户确认的页面与迁移决策

- UI-001 固定采用已确认的 v1 效果图；UI-002 固定采用 `UI-002_颜料失序_纹身工作台_主界面_C_v2.png`。
- 默认视觉基调为清透机能风；UI-002 的“颜料失序”氛围仅作为该页的局部语义，不扩散成通用组件风格。
- 旧产物按用户授权执行“合格保留、不合格清理”。清理前必须依据各页的旧产物审计，排除原始效果图、`结构重制`、源图和文档。
- 只为完整的 UI 状态机补充壳体、遮罩、反馈与图标；角色、纹身、物品、统计内容和预览始终作为运行时内容加载。

## Risks / Trade-offs

- [效果图未展示完整交互状态] → 按交互语义补齐状态，并在素材清单中标为“补充制作”。
- [生成模型改变固定尺寸或绿幕色值] → 在去绿前验证并必要时标准化边界为 `#00ff00`；保留原始生成图审计。
- [通用组件被过度抽象，损失页面语义] → 只有形状和拉伸规则相同的组件进入通用库；含特定图案、稀有度或事件语义的组件留在页面目录。
- [旧产物和新版并存导致误引用] → 新版目录内写明 `结构重制` 标识和素材清单；实现阶段只从新版清单引用。
- [跨页视觉不一致] → 通用资产只生成一套，并在全部页面完成后统一核验边框、圆角、描边与焦点色。

## Migration Plan

1. 创建结构文档和每页素材清单，先完成组件职责与状态确认。
2. 建立通用 UI 组件目录并生成通用壳体。
3. 按页面生成专属壳体与补充状态资源，保留绿幕及切图证据。
4. 对全部最终组件进行透明度、尺寸、命名和复用归属验证。
5. 后续 Prefab 实现只引用新版清单；如需回退，继续使用旧目录而无需删除或还原文件。
