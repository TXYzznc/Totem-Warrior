# 第一阶段可玩版本美术圣经

> 变更：`rebaseline-pvpve-art-resources`  
> 状态：已批准进入文档设计；仅凭本文档不得生产正式资源。  
> 范围：第一阶段 UI、唯一步枪、元素/纹身/反应反馈。明确不包含敌人视觉设计。

## 1. 母风格

世界采用 **清透机能**：一个明亮、干净且具有生活气息的近未来。首张地图的环境基线是已经实现的 **绿洲新城**：暖砂岩、暖白石灰泥、青绿水体、低饱和蓝绿构件、暗木与少量旧铜。环境造型与材质以该场景已有资源为准，本 change 不重新解释或重做场景。

与之形成反差的主题是 **颜料失序**。它只在战斗规则生效时出现，例如纹身触发、元素积累、元素反应、危险与高价值信息。它应当像平静民用系统短暂而受控的失常，不能变成覆盖整个游戏的永久脏污。

### 1.1 三条设计支柱

1. **民用优先于军事**：使用方盒体块、切角外壳、可更换模块、可见维护接缝、安全标记与半透明检查窗。
2. **平静优先于失序**：场景保持暖砂与青绿水体的明亮秩序；UI 使用与其和谐但不相同的深色中性底、暖砂文字和克制青绿焦点；高饱和颜色只占小面积，并且用途明确。
3. **可读性优先于装饰**：先用轮廓、层级、图标形状与播放时序表达规则，再考虑纹理细节。

### 1.2 禁止偏移的方向

- 不得以黑暗战术军事风为基础，不复刻真实武器厂商语言，不使用迷彩或过量导轨。
- 不得让赛博朋克霓虹铺满全屏，不使用永久 RGB 发光、黑铬奢侈材质或没有功能的全息投影。
- 不使用末日脏污、重度锈蚀、血腥、神秘学符号或恐怖表现。
- 本变更不得设计敌人的身体、服装、解剖、轮廓、弱点或动画。
- 玩法信息不得只依赖颜色、微小文字、泛光或屏幕扭曲传达。

## 2. 视觉语法

### 2.1 形状语言

| 含义 | 主要几何形状 | 边缘处理 | 用途 |
|---|---|---|---|
| 民用系统 / 安全 | 方盒、矩形板、阶梯形组合 | UI 以直角或 0–4 px 小倒角为主；3D 使用少分段硬边倒角 | 面板、步枪外壳、中性模块 |
| 操作 / 确认 | 前向楔形、切角前缘、偏移矩形 | 每个物体保留一个清晰方向性切角 | 主按钮、选中状态、枪管方向 |
| 警告 / 不稳定 | 断裂方框、错位棱片、中断折线 | 不规则但保持克制 | 危险、队列压力、反应前兆 |
| 数据 / 档案 | 方格、槽位、索引缺口 | 精确对齐 | 档案、统计、六人情报 |

轮廓采用三级体块：一个主识别方盒体、一个次级切角功能模块，以及少量第三级折面细节。第三级细节缩小到 50% 时应能自然消失，不影响整体识别。

### 2.2 制作成本优先规则

- 方形、矩形、梯形、楔形和低分段折面是默认造型语言；圆形只用于枪管孔、转轴、指示节点等确有功能理由的局部。
- 3D 外轮廓优先通过体块比例、切角和法线分组塑造，不用高分段圆柱或连续曲面堆面数。
- 可见倒角一般使用 1–2 段；只有第一人称近景轮廓经过验证后才允许增加分段。
- 能以贴图、法线或共用装饰件表达的细节，不额外切割主体拓扑。
- UI 面板优先共用矩形九宫格与切角角片，避免为大量不同圆角半径制作独立资源。
- VFX 优先使用方片、棱片、条带和低面数网格；圆环特效默认改为断裂方框或多段折线框。

### 2.3 色彩系统

以下数值是初始设计目标，最终必须在项目实际色调映射下进行引擎内检查。

| 色彩令牌 | 色值 | 用途 |
|---|---:|---|
| `UI/SandText` | `#EFE3CD` | UI 主要亮文字与高对比细线；与场景暖砂和谐但不模拟石材 |
| `UI/MistStone` | `#9DABA6` | 次级文字 / 非激活结构 |
| `UI/Slate` | `#506567` | 次级边框与分隔线 |
| `UI/DeepInk` | `#1C272B` | 高对比半透明面板与 HUD 底板 |
| `UI/FocusTeal` | `#379091` | 中性焦点、导航与系统反馈；亮度低于场景水体 |
| `UI/Copper` | `#B7824F` | 极少量层级分隔和确认细线，不作为大面积装饰 |
| `State/Positive` | `#59C38C` | 恢复 / 救援成功 |
| `State/Warning` | `#F2B84B` | 紧迫 / 倒计时将结束 |
| `State/Danger` | `#E65B61` | 致命危险 / 即将淘汰 |
| `Element/Fire` | `#F0643C` | 火；配合上升楔形与火星节奏 |
| `Element/Ice` | `#62C7E8` | 冰；配合方形 / 菱形板块与内收节奏 |
| `Element/Lightning` | `#B684F4` | 雷；配合分叉折线与脉冲节奏 |

普通画面的色彩占比目标：中性色 75–90%，导航/状态色 5–15%，颜料失序 0–10%。反应峰值可在目标附近短暂达到 20%，但必须在一秒内恢复。

### 2.5 领域隔离规则

- **环境**：完整继承绿洲新城已有建筑、材质、植被、水体与光照语言。
- **UI**：只要求与当前场景色彩和谐；不得复制马赛克、釉面纹样、拱券、风塔或建筑装饰。UI 的形状仍由信息层级、方形/切角和制作成本决定。
- **VFX**：不继承场景色板、材质或纹样。火、冰、雷及元素反应按玩法可读性独立设计，只需在实际场景明暗背景上通过可读性与遮挡验收。
- **武器**：继续使用已确认的民用模块化巡防语言，不因场景配色机械改色。

### 2.4 对比度与色盲适配合同

- 正文和重要图标的对比度目标至少为 4.5:1；大号展示文字至少为 3:1。
- 火、冰、雷必须同时使用 **形状 + 动作节奏 + 图标** 区分，不能只靠色相。
- 弱、标准、强分别使用一、二、三个结构标记，并逐级增加占用面积，不能只提高亮度。
- 焦点状态使用 3 px 描边加前导楔形；禁用状态降低对比度并显示锁定或不可用标记。
- 关闭泛光与色差效果后，关键警告仍须清晰可读。

## 3. 材质与表面语言

### 3.1 共用材质

| 材质族 | 外观 | 粗糙度目标 | 常见用途 |
|---|---|---:|---|
| 喷涂民用合金 | 暖白或浅灰蓝，细微橘皮喷涂质感 | 0.55–0.75 | 武器外壳、公共设备 |
| 深色结构聚合物 | 炭灰蓝、低高光、轻微注塑接缝 | 0.65–0.85 | 握把、UI 深色底板、防撞部件 |
| 拉丝维护金属 | 克制的单向拉丝，不得镜面反射 | 0.35–0.55 | 枪管核心、紧固件、工作导轨 |
| 检查窗聚合物 | 轻微着色的半透明面板 | 0.2–0.4 | 弹药 / 状态检查窗 |
| 颜料能量 | 仅在事件峰值时高饱和与自发光 | 不适用 | 元素通道与反应反馈 |

磨损只允许出现在接触边缘、维护螺丝和握持区域。禁止大面积污垢遮罩、随机划痕和虚假微缩文字。贴花必须用于表达维护、安全或模块身份。

### 3.2 自发光纪律

中性硬件的自发光必须低强度且局部化。元素自发光可以在触发瞬间达到峰值，但除非玩法状态持续，否则必须在 0.6 秒内回到待机状态。过曝白芯只保留给元素反应中心，在 60 帧基准下最多持续 3 帧。

## 4. UI 美术方向

UI 与绿洲新城的关系仅限色彩协调：深墨灰面板在明亮砂岩场景上提供稳定对比，暖砂文字避免冷白突兀，低亮青绿用于焦点和导航。不得把场景马赛克、釉面、拱券或建筑纹样搬进 UI。

### 4.1 构图

- 参考画布：1920×1080，`Scale With Screen Size`，匹配值 0.5。
- 关键内容位于 90% 标题安全区内；交互目标位于 93% 操作安全区内。
- 界面使用大块留白和两到三个清晰体块。只有档案、情报和结算页面可以使用密集卡片墙。
- 战斗 HUD 靠近屏幕边缘，屏幕中央的瞄准与战斗识别区域保持干净。

### 4.2 字体排版

- 使用支持中日韩字符、等宽数字与清晰标点的无衬线字体；最终授权字体由生产阶段决定。
- 1080p 下正文最小 16 px；普通交互文字 20 px；关键 HUD 数字至少 24 px。
- 单屏最多使用两种字重。全大写拉丁字符只用于短标签与资源 ID。
- 高频变化数字使用等宽数字和固定宽度容器，避免布局抖动。

### 4.3 图标

- 交付图标画布最小为 64×64；缩放到 32×32 显示时必须仍然可读。
- 64×64 下目标描边宽度为 3 px，端点使用平头或小切角。轮廓在单色显示时仍须成立。
- 火：向上分裂楔形。冰：方形 / 菱形内收板块。雷：错位分叉闪电。
- P01 与 P02 除文字外还要使用不同的单框 / 分裂方框轮廓；对手永远看不到精确效果数值。

### 4.4 动效

- 标准焦点 / 选择反馈：80–140 毫秒；页面转场：140–200 毫秒。
- 紧急信息不得使用过冲动画。民用 UI 使用短距离归位，颜料事件使用断线显现。
- 减少动态效果模式用透明度 / 描边变化替代位移与缩放，同时保留事件顺序。
- 玩法规格要求的 UI 倒计时使用不受时间缩放影响的时间。

## 5. 武器美术方向

第一阶段唯一武器是 **民用模块化巡防步枪**，它源自市政维护与周界安全设备。其识别特征包括：方盒式封闭上机匣、一体化切角提把 / 瞄具桥、中等长度枪管、折面防护护木、可替换握把模块，以及半透明弹匣 / 状态检查窗。

它在第一和第三人称下都必须清楚地被识别为步枪，同时不能复制真实枪械。平静的中性色主体占主导；颜料只在元素或纹身事件发生时短暂流经狭窄维护通道。详细结构与预算见 `weapon/WPN-FP-001_rifle-design-brief.md`。

## 6. 战斗反馈语言

本节是独立的战斗表现语言，不引用绿洲新城的配色、材质和装饰纹样。场景只作为后续测试背景之一。

| 类别 | 形状 | 动作 | 音效交接意图 | 持续方式 |
|---|---|---|---|---|
| 火 | 上升楔形、火星碎屑 | 向上加速 | 干燥点燃声 / 短促噼啪声 | 分层灼烧状态 |
| 冰 | 内收方板 / 菱形板、边缘冰晶 | 收缩、保持、释放 | 玻璃锁定声 / 受抑尾音 | 分层减速状态 |
| 雷 | 分叉折线、节点脉冲 | 不连续跳跃 | 锐利脉冲 / 短电弧声 | 按事件触发，不持续制造噪声 |
| 热冲击 | 冷暖分裂方框向内坍缩 | 汇聚后沿四向释放 | 双音色脆响 | 终结爆发 |
| 过载 | 三节点折线电弧 | 中心充能后以断裂多边框扩张至 3 米 | 电压释放爆音 | 终结爆发 |
| 停滞 | 交叉冰 / 雷框架 | 夹紧并低频脉冲 | 受抑锁定声 | 2 秒可读状态 |

VFX 只负责表现。伤害、选定目标、反应结算与队列排序全部归玩法系统所有。特效只消费已经结算的事件数据并挂载到通用目标锚点，不得推断敌人类型或弱点解剖结构。

## 7. 镜头与可读性目标

- 第一人称步枪：可见机匣、瞄具桥与状态窗，同时不得遮挡屏幕中央准星。
- 第三人称步枪：15 米距离下仍能区分枪管、主体与枪托体块；元素通道只作为次级信息。
- UI 与世界特效必须在 720p、1080p、4K 和掌机级屏幕上保持可理解。
- 第一阶段以 PC 60 帧为验证基准，手柄优先，同时保证键鼠操作一致。

## 9. 审核门槛

生产任何正式资源前，用户必须确认：

1. 本文档中的母风格与禁止偏移清单；
2. `prefab-layout.md` 的全部页面状态与焦点路径；
3. 步枪轮廓和材质设计；
4. VFX 语言与性能预算；
5. `prompts.md` 中用于生成的提示词。

特效与粒子在生产后必须先进入 `Assets/Game/Scene/ArtResourceTest.unity` 独立测试场景调试，通过明暗背景、第一 / 第三人称、同屏压力、画质降级和构建版本复测后，才允许接入正式流程。

确认后，生产阶段按可回退的小批次推进。不得覆盖现有保留资源；候选资源只有在来源与授权核验完成后才能复制到新的交付路径。
