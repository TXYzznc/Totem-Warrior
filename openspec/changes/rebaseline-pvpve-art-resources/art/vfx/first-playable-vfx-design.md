# 第一阶段可玩版本 VFX 设计

> 适用于步枪、元素层数、元素反应和纹身事件反馈的纯表现合同。敌人设计不属于本变更。

## 1. 运行时边界

VFX 只接收已经结算的事件与表现数据。允许读取事件类型、层级、世界坐标、通用目标包围盒、来源 / 目标队伍关系、无障碍设置与画质设置。不得计算伤害、选择目标、排列纹身事件、决定元素反应或检查敌人解剖结构。

通用挂载合同：

| 锚点 / 数据 | 缺失时的回退方式 |
|---|---|
| `Socket_Muzzle`，枪口锚点 | 武器包围盒前端 |
| `Socket_ElementRail`，元素通道锚点 | 武器 Renderer 包围盒中心 |
| 已结算命中点与法线 | 目标包围盒中心 + 朝向镜头的法线 |
| `VFX_TargetCore`，目标核心 | 目标 Renderer 包围盒中心 |
| `VFX_StatusTop`，状态顶部 | 目标包围盒顶部再向上 0.2 米 |
| `VFX_TattooSlot_*`，纹身部位 | 回退至目标核心，并使用部位类别的屏幕图标 |

锚点缺失时必须以明显但安全的方式降级。任何特效播放失败都不得改变模拟结果。

## 2. 元素层数语言

| 元素 | 形状 | 节奏 | 弱 / 标准 / 强 |
|---|---|---|---|
| 火 | 上升分裂楔形 + 稀疏火星 | 快速上升、柔和下落 | 1 / 2 / 3 条楔形带 |
| 冰 | 内收方板 / 菱形板 + 边缘冰晶 | 收缩、保持、释放 | 1 / 2 / 3 层嵌套方板 |
| 雷 | 分叉折线 + 节点 | 不连续双脉冲 | 1 / 2 / 3 个活动节点 |

施加提示持续 0.28–0.45 秒。目标上的持续状态保持克制：在距离目标 5 米时，最大屏幕占用约为目标高度的 12%。每 3 秒衰减一次时，用 0.18 秒反向节奏移除一个结构标记。层数完全由事件数据驱动。

持续状态提示与施加提示分离：

| 状态事件 | 表现方式 |
|---|---|
| 火焰灼烧，每次已结算的 0.5 秒 tick | 从现有标记中升起一个小火焰楔形，不增加第二次命中闪光 |
| 冰霜减速 | 切角方框围绕通用目标核心轻微收缩；12/20/28% 层级分别使用 1/2/3 层方板 |
| 雷电放电 | 一条分支只跳向玩法已经结算的次级目标；自身回流在来源处显示半强度闭合回路 |

这些效果只响应已经结算的 tick 或连接事件。它们不自行计时、不寻找最近目标，也不计算 50% 自身回流。

事件 key：

```text
vfx.element.fire.apply.weak
vfx.element.fire.apply.standard
vfx.element.fire.apply.strong
vfx.element.ice.apply.weak
vfx.element.ice.apply.standard
vfx.element.ice.apply.strong
vfx.element.lightning.apply.weak
vfx.element.lightning.apply.standard
vfx.element.lightning.apply.strong
vfx.element.stack.decay
vfx.element.fire.burn_tick
vfx.element.ice.slow
vfx.element.lightning.discharge
vfx.element.lightning.self_return
```

## 3. 元素反应分镜

时序以 60 帧为参考，并按真实时间缩放；玩法模拟时间不得由这些表现时序推导。

### 3.1 热冲击——`vfx.reaction.heat_shock`

| 帧数 | 表现 |
|---:|---|
| 0–3 | 火焰楔形和冰霜板块出现在目标核心两侧 |
| 4–8 | 两者向内坍缩；核心周围饱和度短暂降低 |
| 9–11 | 冷暖分裂方框沿四向释放；白色中心持续 1–2 帧，不得覆盖全屏 |
| 12–24 | 短促的蒸汽状颜料带向上消散 |

阅读含义：两个不相容状态被强制中和。效果范围应紧贴目标，因为规则是单体 `0.6 × 步枪本体伤害`。

### 3.2 过载——`vfx.reaction.overload`

| 帧数 | 表现 |
|---:|---|
| 0–4 | 三个雷电节点围绕高温中心相连 |
| 5–9 | 三角压力框向内压缩 |
| 10–13 | 中心爆点与贴地 3 米断裂多边框同时扩张；边数保持低，整体读作方形冲击边界 |
| 14–30 | 次级电火花只沿玩法已经结算的受影响方向传播 |

阅读含义：中心目标加邻近目标。中心使用更重的核心形状，周围接触点使用更细的分叉标记。VFX 不自行寻找附近目标，只接收已结算的位置列表。

### 3.3 停滞——`vfx.reaction.stasis`

| 时间 | 表现 |
|---:|---|
| 0–0.18 秒 | 交叉冰框与雷电夹具闭合到目标核心 |
| 0.18–1.8 秒 | 每 0.6 秒进行一次低频双脉冲；保持克制的持续轮廓 |
| 1.8–2.0 秒 | 框架打开，碎片向内收回而不是爆炸 |

阅读含义：输出被限制 2 秒。使用方形括号轮廓，避免被误解为完全冻结或眩晕。

## 4. 步枪与命中反馈

| 事件 | 持续时间 | 设计 |
|---|---:|---|
| `vfx.weapon.rifle.muzzle` | 0.08–0.12 秒 | 紧凑的民用信号蓝核心加当前元素边缘，不使用巨大火球 |
| `vfx.weapon.rifle.tracer` | 不超过 0.10 秒 | 细窄分段维护线；可按距离 / 画质关闭 |
| `vfx.weapon.rifle.hit_body` | 0.18 秒 | 小型内收括号，然后释放少量碎屑 |
| `vfx.weapon.rifle.hit_weakpoint` | 0.26 秒 | 双菱形断裂 + HUD 确认；保持通用，不包含解剖设计 |
| `vfx.weapon.rifle.element_channel` | 0.35 秒 | 已结算元素事件后，颜料沿武器维护通道流动 |

枪口焰不得遮挡瞄准画面。第一人称与第三人称共享同一个事件身份，但分别使用独立的表现尺寸和透明度倍率。

## 5. 纹身事件队列反馈

事件顺序由玩法提供。VFX 只按顺序镜像播放，不重新排序：

| key | 优先级来源 | 提示形态 |
|---|---:|---|
| `vfx.queue.p01` | 事件数据 | 实心单层方框，一次向内颜料扫过 |
| `vfx.queue.p02` | 事件数据 | 分裂双层方框，两次错位扫过 |
| `vfx.queue.dodge` | 90 | 横向断裂线 |
| `vfx.queue.move` | 80 | 向前箭头轨迹 |
| `vfx.queue.weakpoint` | 70 | 双菱形脆响式收合 |
| `vfx.queue.rifle_arm` | 60 | 狭窄武器通道脉冲 |
| `vfx.queue.torso` | 50 | 宽阔中心断裂方框 |

主动技能优先级 100 由玩法预留；本美术变更只提供中性回退提示，不创造技能视觉。HUD 队列项进入时使用 90 毫秒显现，相邻项目间隔 40 毫秒，结算退出用 140 毫秒。零延迟模式可以压缩间隔，但必须保留顺序。

## 6. 性能预算

| 特效类别 | CPU 粒子峰值 | 材质数 | 目标 Draw Call | 最长时间 | 同屏上限 |
|---|---:|---:|---:|---:|---:|
| 步枪枪口 / 命中 | 24 / 36 | 1 | 1 | 0.26 秒 | 12 |
| 元素施加：弱 / 标准 / 强 | 32 / 52 / 72 | 1–2 | 不超过 2 | 0.45 秒 | 10 |
| 持续元素层数标记 | 12 | 1 | 1 | 状态驱动 | 6 个目标 × 3 个标记 |
| 热冲击 | 90 | 2 | 不超过 3 | 0.45 秒 | 4 |
| 过载 | 140 | 2 | 不超过 3 | 0.55 秒 | 3 |
| 停滞 | 70 | 2 | 不超过 2 | 2.0 秒 | 4 |
| 纹身队列世界提示 | 40 | 1 | 1 | 0.35 秒 | 8 |

第一阶段以 PC 60 帧为基准。特效使用对象池；只有性能分析证明有价值时才预热粒子系统。禁止每次事件创建运行时材质、每帧查找字符串或在事件处理中使用产生大量分配的 LINQ。基础版本不使用 Shader 扭曲；低画质首先移除曳光、环境碎屑与次级电弧，结构性提示必须保留。

### 6.1 形状与制作成本

- 粒子贴片默认使用方片、矩形条带、三角 / 梯形棱片和低面数网格；不以高分段圆环或球壳作为主结构。
- 需要环状传播时，优先使用四段断裂方框、八段以内折线框或四向条带，而不是完整圆环网格。
- 核心识别层最多 1 个材质，辅助层最多再增加 1 个；共用同一张 VFX 图集时优先复用。
- 视觉复杂度优先通过时序、缩放曲线和方向组合获得，不依靠增加粒子数与网格面数。
- 圆形可以作为枪口孔、微小能量节点或 1–2 帧爆点，但不得成为整套效果的主要轮廓语言。

## 7. 独立美术资源测试场景

后续生产必须创建 `Assets/Game/Scene/ArtResourceTest.unity`，作为特效、粒子、材质与武器表现的独立调试场景。任何相关资源在进入正式流程前，都必须先在此场景达到审核标准。

### 7.1 场景结构合同

```text
ArtResourceTest
├─ Environment
│  ├─ NeutralLightRig          # 中性主光
│  ├─ BrightBackground         # 浅色背景测试
│  ├─ DarkBackground           # 深色背景测试
│  └─ GameLookVolume           # 与正式流程一致的后处理基准
├─ CameraRig
│  ├─ FirstPersonCamera        # 第一人称距离
│  ├─ ThirdPersonCamera        # 第三人称距离
│  └─ InspectionCamera         # 静态近景检查
├─ Workbench
│  ├─ WeaponMount              # 武器挂架与枪口/元素锚点
│  ├─ TargetProxy_Box          # 不带敌人造型的方盒目标代理
│  ├─ HitPointGrid             # 命中位置网格
│  └─ VFXSpawnGrid             # 单个与多实例生成位置
├─ StressArea
│  ├─ SixParticipantMarkers    # 六名参与者位置代理
│  └─ ConcurrentEffectSlots    # 按预算测试同屏上限
└─ TestUI
   ├─ EffectSelector           # 选择资源
   ├─ PlayOneShot              # 单次播放
   ├─ LoopToggle               # 循环开关
   ├─ QualitySelector          # 画质等级
   ├─ TimeScaleSelector        # 正常/慢放/暂停检查
   └─ MetricsPanel             # 粒子、Draw Call、帧时间、Overdraw 记录
```

测试 UI 的全部操作必须通过项目 InputModule 与 `TotemInputService` / `ITotemInputProvider`，不得在场景脚本中直接轮询键盘或手柄按键。

### 7.2 调整与晋级流程

1. 在中性背景下完成单个特效的形状、预备、爆发和余韵调整。
2. 切换浅色 / 深色背景及灰度观察，保证不依赖色相仍可辨。
3. 使用第一 / 第三人称相机检查准星遮挡、近裁剪、目标覆盖和尺寸。
4. 使用同屏上限与六参与者压力布局检查粒子峰值、透明排序、Overdraw、Draw Call 和帧时间。
5. 切换低 / 中 / 高画质，确认核心形状保留，辅助粒子按顺序降级。
6. 使用与正式流程一致的后处理再次检查颜色与泛光。
7. 在目标平台构建版本中复测，排除编辑器与构建的色彩、时序、质量级别差异。
8. 美术、技术美术与主玩法共同签署通过记录后，才允许把资源 key 接入正式流程。

### 7.3 通过标准

- 单独观看时形状与时序达到设计目标；放入压力布局后仍不遮挡准星、关键 HUD 与目标轮廓。
- 粒子数、材质数、Draw Call、同屏上限和 Overdraw 不超过本文预算。
- 浅色、深色、灰度、低画质和减少动态效果模式均保持核心含义。
- 循环效果无明显接缝；一次性效果没有残留对象；对象池重复播放不改变结果。
- 编辑器与构建版本的颜色、播放速度和透明排序无不可接受差异。
- 未达到以上任何一项时继续留在测试场景调整，不得进入正式流程。

## 8. 无障碍与遮挡

- 色彩饱和度降到零时，形状编码的核心信息仍须成立。
- 减少动态效果模式用 2–3 个透明度 / 描边步骤替代移动，不得删除顺序信息。
- 目标位于镜头后方或完全离屏时，只有玩法明确请求标记才显示 HUD 指示器。
- 屏幕中央附近的反应覆盖范围必须受限，准星和目标轮廓始终可见。
- 友方 / 敌方来源关系可以改变描边处理，但不得通过颜色推断效果结果。

## 9. 验证要求

- 对比开启与关闭 VFX 的运行结果：模拟结果和有序事件日志必须相同。
- 测试锚点缺失、材质缺失、对象池耗尽以及特效播放中目标被销毁。
- 在 720p、1080p、4K 和掌机显示比例下测试弱 / 标准 / 强三层。
- 使用六名活跃战斗参与者、文档规定的并发上限和具有代表性的步枪开火进行压力测试。
- 在单色截图和减少动态效果模式下，验证火 / 冰 / 雷及全部反应仍可区分。
- 验证所有资源、命名和轮廓均未引入敌人视觉设计依赖。
