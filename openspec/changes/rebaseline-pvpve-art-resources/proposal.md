## Why

玩法已从旧的多人、多武器、七元素、随时纹身与局外熟练度方案收敛为 6 人双排、单枪械、三轮第一阶段和分轮构筑，现有 UI 交付虽然完整，但信息结构已经失效。需要建立一份独立美术生产计划，使美术工作可在单独窗口推进，同时不阻塞主玩法用占位资源完成验证。

## What Changes

- 确认首张地图场景、建筑、场景相关 3D、角色相关 3D、六部位纹身贴花/遮罩和八图案视觉库继续使用，不重复生产。
- **BREAKING**：旧 `UI-001`～`UI-005`、七元素图标和通用 UI 组件不再作为当前最终交付；保留原文件作为历史参考或复用候选。
- 为主菜单、第一阶段 HUD、分轮构筑、六人情报、队友颜料请求、倒地/救援/淘汰和三轮结算建立新的 UI 结构、视觉稿、切片与验收任务。
- 第一阶段元素视觉只覆盖火/冰/雷与弱/标准/强三层；图案只实现 P01/P02，但保留 P01～P08 的现有视觉库。
- 第一阶段只设计一款基础枪械；旧短刀、重锤、弓和能量拳套概念不进入生产。
- 敌人造型、材质、动画和非人型弱点标记移出本 change，后续由独立敌人美术设计任务处理；本 change 的 VFX 只提供不依赖敌人造型的通用附着与遮挡合同。
- 重做火/冰/雷状态、热冲击/过载/停滞反应、纹身触发和事件队列结算反馈所需 VFX；Boss/撤离/第 4/5 轮资产延后。
- 全部新造型以方盒、矩形、切角和低分段折面为主，圆形仅作功能性局部；把面数、材质数、复用率和制作工时纳入美术验收。
- 后续在 `Assets/Game/Scene/ArtResourceTest.unity` 建立独立美术资源测试场景；特效和粒子必须先在该场景完成视觉、遮挡、性能和构建复测，再进入正式流程。
- 以 `artifacts/美术资源需求/美术资源需求表.xlsx` 为唯一状态台账，并建立可被主玩法 change 消费的资源 ID、路径、尺寸、状态和验收证据。

## Capabilities

### New Capabilities

- `first-playable-ui-art`: 第一阶段全部菜单、HUD、构筑与反馈界面的结构、视觉、切片和适配交付。
- `first-playable-combat-art`: 单枪械、三元素与纹身/反应 VFX 的最小生产范围；不包含敌人资产设计。
- `pvpve-art-handoff-contract`: 美术台账、稳定资源 ID、历史资源保留、交付路径、导入状态和验收证据。
- `retained-pvpve-visual-assets`: 对场景、角色 3D 与纹身资源的继续使用范围、复用检查和禁止重复生产规则。

### Modified Capabilities

- `gameplay-character-art`: 角色相关 3D 不重新定风格或重做母版，只验证与六部位纹身和当前运行时的兼容性。
- `ui-planning`: UI 规划从旧完整产品界面清单改为第一阶段三轮可玩闭环，并强制执行结构先行的生产顺序。
- `visual-polish`: 视觉打磨聚焦战斗信息可读性和元素层级，不扩展到敌人资产、Boss、撤离或完整局外成长。

## Impact

- 主要影响 `artifacts/美术资源需求/`、新 change 的 `art/` 目录、UI layout/mockup/slicing 产物，以及最终进入 runtime asset catalog 的资源文件。
- 不修改玩法公式、C# 业务逻辑、DataTable 规则、网络协议或 GF_X 框架；这些全部归属 `rebuild-six-player-pvpve-first-playable`。
- UI Prefab 拼装和运行时接线归主玩法 change；本 change 交付结构契约与素材，并通过可替换占位资源解除双方阻塞。
- 旧美术文件不删除；状态必须明确为“继续使用”“已完成-需返工”“暂不需要”或新的待设计/待制作阶段。
