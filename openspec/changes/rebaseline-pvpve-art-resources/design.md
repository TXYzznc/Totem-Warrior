## Context

`artifacts/美术资源需求/美术资源需求表.xlsx` 已按新玩法重置为 118 条：场景/角色 3D 与纹身继续使用，旧 UI 分为“已完成-需返工”与“暂不需要”，并新增 UI-006～UI-008。首张地图场景和风格已经确认，当前最大缺口不是环境重做，而是旧 UI 信息结构、五武器/七元素概念和旧 PVE 范围与第一阶段不一致。

美术将在独立窗口推进，程序 change `rebuild-six-player-pvpve-first-playable` 同时用占位资源实现功能。两边必须通过稳定的资源 ID、布局合同和验收状态协作，不允许美术任务隐式修改玩法，或程序为了等待效果图停摆。

## Goals / Non-Goals

**Goals:**

- 明确哪些现有资源继续使用、哪些仅为历史参考、哪些需要重做。
- 为第一阶段 UI 建立结构先行、效果图、切片、导入与多分辨率验收的完整生产链。
- 生产最小单枪械和三元素/VFX 契约；敌人资产后续单独设计。
- 保持纹身八图案视觉库，但只为 P01/P02 制作第一阶段 UI/VFX 适配。
- 让每项交付都能由台账、路径、稳定 ID 和截图/导入证据追溯。

**Non-Goals:**

- 不重做首张地图、24 栋建筑、已确认场景装饰、角色母版或六部位纹身库。
- 不制作 Boss、撤离点、第 4/5 轮、高阶资源、P03～P08 功能表现、额外武器或局外熟练度。
- 不编写 C#、修改玩法数值、DataTable 规则、网络或 GF_X 框架。
- 不直接拼装最终运行时 UI Prefab；美术交付 layout 和素材，程序 change 负责接线与 Prefab 实现。

## Decisions

### Decision 1: 复用资产先审计，不重复生产

候选方案：A 全部重做以统一风格；B 直接把现有文件全视为完成；C 按台账逐项确认“继续使用/需返工/暂不需要”。选择 C。场景、角色 3D 与纹身默认保留，但仍做一次命名、导入、六部位可见性和运行时路径检查；检查不等于重新创作。

### Decision 2: UI 严格执行结构先行六阶段

顺序固定为：`prefab-layout.md → 用户确认结构 → 效果图提示词 → 用户确认提示词 → 效果图生成/确认 → 素材拆分 → 程序拼装 → 联调微调`。不得先生成漂亮整图再反推不可实现的布局。layout 必须给出 720p、1080p、4K 和掌机 fallback，控制器焦点优先，同时兼容键鼠。

### Decision 3: 旧 UI 不覆盖，另存为历史参考

旧 `UI-001`～`UI-005` 与 `通用UI组件` 原文件保持不动；新设计进入对应条目的“重设计”目录或 UI-006～UI-008 新目录。验收通过后更新台账状态和 runtime 交付路径，不用同名覆盖来伪造版本历史。

### Decision 4: 动态数据与静态美术分离

玩家名、数值、倒计时、颜料数量、队伍颜色、元素层数和构筑效果文本不得烘焙进 PNG。素材只提供九宫格壳体、图标、背景、遮罩和状态层；文字、颜色和数量由程序注入。元素语义同时使用颜色、形状和层级刻度，不能只靠红/蓝/黄区分。

### Decision 5: 第一阶段只生产一把低成本方盒式巡防步枪

唯一枪型已确认为“民用模块化巡防步枪”。轮廓以方盒、梯形、楔形、切角与低分段折面组合为主；圆形只保留给枪口孔、转轴等功能性局部。旧手枪概念不能自动成为最终答案，旧短刀/重锤/弓/拳套不继续生产。正式模型仍须经过完整设计包确认。

### Decision 6: 敌人资产从本 change 解耦

本 change 不定义三类敌人的轮廓、比例、材质、动画、弱点位置或 Prefab。元素/VFX 只描述通用目标附着点、包围盒比例、遮挡优先级和程序事件 key；任何敌人专属适配必须等待后续独立敌人美术设计任务确认。

### Decision 7: VFX 服从模拟队列，不制造第二套规则

美术只定义每个事件的预警、命中、层级、反应、结算顺序和间隔表现。VFX 不自行判断伤害、不持有反应冷却、不生成新事件。火每 0.5 秒 tick、三层元素、热冲击/过载/停滞和 P01/P02 必须有尺寸、颜色、持续时间和遮挡预算。

### Decision 8: 台账是唯一状态源

任何新资源先登记 ID、路径、说明和初始状态；只有布局/概念/正式资产/Unity 导入分别达到对应门槛才推进状态。OpenSpec task 勾选不能替代台账状态，台账状态也不能替代运行时验收。

### Decision 9: 方形主语言与独立美术测试场景

UI、武器和 VFX 默认使用方盒、矩形板、梯形、楔形、切角和低面数棱片。圆形允许存在，但必须有功能理由且不能主导造型。特效与粒子生产后统一进入 `Assets/Game/Scene/ArtResourceTest.unity` 调试：依次完成中性/明暗背景、第一/第三人称、六人同屏压力、画质降级、Overdraw 和构建版本复测。未在该场景通过的资源不得接入正式流程。测试场景的全部交互必须走项目 InputModule。

## Risks / Trade-offs

- [旧 UI 很完整，容易被误认为可直接复用] → 所有旧目录写清历史状态，新稿使用独立版本路径和截图证据。
- [美术先于枪型决策导致返工] → 枪械分为 brief/轮廓确认与正式生产两道 gate，未确认只做占位合同。
- [六人情报面板信息过载] → layout 先做信息层级和折叠策略，1080p/720p 原型通过后才出效果图。
- [三元素只靠颜色影响色盲可读性] → 每个元素必须有独立轮廓、纹理节奏和层级符号，并执行红绿/蓝黄/全色盲模拟。
- [VFX 遮挡射击与弱点] → 定义屏幕占比、亮度和同屏数量预算；弱点提示优先级高于装饰粒子。
- [圆润造型提高面数与制作工时] → 方形与切角体块优先；倒角默认 1 段、近景主轮廓最多 2 段；圆形局部必须说明功能理由。
- [孤立预览好看但正式流程失效] → 先在独立美术测试场景调到通过，再进行目标平台构建复测和正式接入。
- [两个窗口同时改资源表] → 美术窗口拥有台账和美术目录；主玩法窗口只读资源状态，若需接口变更通过 handoff 文档提出。

## Migration Plan

1. 保存旧 UI/武器/元素目录与台账状态，不删除资源。
2. 完成 retained-asset audit，并把继续使用资源的真实导入/兼容结论写回台账。
3. 为所有第一阶段 UI 输出信息架构与 `prefab-layout.md`，逐组确认后再进入效果图。
4. 冻结枪械轮廓与生产 brief；生成/制作正式资源并建立 Unity 可消费交付包。
5. 创建 `Assets/Game/Scene/ArtResourceTest.unity`，制作三元素、三反应、P01/P02 和事件队列 VFX，并在该场景验证明暗背景、第一/第三人称、遮挡、节奏、画质降级和性能。
6. 拆分 UI 素材、更新资源 ID/路径，交给主玩法 change 拼装。
7. 完成 720p/1080p/4K/掌机、色盲、导入、性能和运行时截图验收，再更新台账状态。
