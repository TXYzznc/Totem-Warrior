## Context

当前地形视觉链路同时包含基础地形、方向边、角块、transition mask、detail、underlay、旋转/翻转 orientation、edge signature 与 socket 匹配。该结构要求大量专用资源，并把主要复杂度放在消除接缝上，但用户已确认接受同种地貌纹理跳变和不同地貌直接硬拼。

本轮是草地—河流视觉试制。用户确认：每种地貌 8 个 256×256 变体、每对交界 6 个透明装饰；资源必须由绘图模型绘制；地貌图块必须铺满画布且四边无透明像素；装饰允许不同尺寸。通过 Unity 实际拼接预览后，才继续生产其他地貌资源。

## Goals / Non-Goals

**Goals:**

- 用最小数据模型表达地图地貌清单、地貌图块池和地貌对装饰池。
- 让同一 seed 下图块与装饰随机结果可复现，并允许未来通过权重、标签替换选择策略。
- 生成并验证草地 8 张、河流 8 张、草地—河流装饰 6 张。
- 在 Unity 中展示不依赖边缘拼图或融合图的直接拼接效果。

**Non-Goals:**

- 本轮不制作其他地图或其他地貌的正式美术资源。
- 不要求同地貌图块无缝，不制作 N/E/S/W 方向边、角块、融合 mask 或过渡带。
- 不实现通用规则 DSL、生态模拟、装饰聚类器或运行时纹理合成。
- 在试制通过前不删除旧 catalog、旧切片资源或旧生成路径。

## Decisions

### 1. 图块是独立满画布底图

每张地貌图块最终为 256×256 PNG。四条边及四角均必须被地貌内容覆盖，alpha 必须为 255；不要求左右或上下像素连续。选择该方案是为了消除透明边造成的物理缝隙，同时不重新引入无缝纹理制作成本。

替代方案是继续制作 seamless tile；它能降低纹理跳变，但与用户明确接受“不无缝”相冲突，并显著提高生成、筛选和修图成本。

### 2. 地貌池只保存稳定元数据

地貌池条目使用 `terrainId`、`variantId`、`assetKey`、`weight`、`tags`。试制期所有权重为 1，按 seed 做加权随机；未来规则只需过滤标签或调整权重，不改变资源格式。

不在条目中保存 socket、方向边、邻接签名、旋转组合或边缘占比。

### 3. 装饰池以无方向地貌对为键

交界装饰按排序后的无方向键保存，例如 `grass|river`，每个地貌对 6 个条目。条目记录 `decorationId`、`assetKey`、`canvasPixels`、`worldFootprint`、`weight`、`tags` 与 `allowQuarterTurns`。草地—河流试制默认不自动镜像；长条资源可显式允许 90° 旋转。

边界检测只检查四邻域不同地貌的共享边。每段共享边以稳定哈希判断是否放置装饰，再从池中随机选择并放在边界附近；装饰是点状/簇状环境物，不承担完全遮住整条接缝的责任。

### 4. 绘图模型负责图像内容，程序只做图集切分与布局

所有纹理和装饰主体由 imagegen 绘制。同一张源画布只能包含一种地貌：8 个草地变体在一张 4×2 无间隔源画布中绘制，8 个河流变体在另一张 4×2 无间隔源画布中绘制，6 个装饰在一张 3×2 洋红底源画布中绘制。程序只允许进行不创造视觉内容的机械后处理：把源画布中心裁到目标网格宽高比、等分切图、缩放、色键抠图、PNG 编码、尺寸与 alpha 验证。禁止用噪声、图形绘制或像素算法合成地貌纹理、岸线或融合边。

### 5. 先试制、后切换

资源先进入 `openspec/changes/simplify-pcg-terrain-pipeline/art/raw/`。Unity 预览使用独立 pilot catalog/scene 或调试入口，不替换正式运行时默认路径。用户确认视觉效果后，再导入正式资源目录、切换运行时并清理旧方案。

## Risks / Trade-offs

- [图块之间出现明显纹理跳变] → 统一色板、光照方向、像素密度和细节频率；接受局部跳变，不为此恢复边缘拼图。
- [模型生成结果带网格线、边框或透明边] → 源画布要求无 gutter、无 grid line、每格 full-bleed，并对切图四边 alpha 和覆盖率做自动拒收。
- [河流水流方向在相邻块间冲突] → 首轮使用低方向性的涟漪与短流纹，强方向变体仅占少数；后续可用标签规则选择。
- [透明装饰色键抠图污染绿色植物] → 使用纯洋红 `#ff00ff` 色键并执行 despill/alpha 检查。
- [装饰密度过高或重复] → 试制以固定 seed、spawn chance 和最小间距预览，暂不引入复杂生态规则。
- [与旧 PCG 改动冲突] → pilot 路径隔离，旧资源和旧 catalog 保留到用户验收后。

## Migration Plan

1. 分别生成 1 张 4×2 草地源画布、1 张 4×2 河流源画布和 1 张 3×2 装饰源画布，切分并验证 22 张 pilot 资源，保留生成记录与提示词。
2. 建立仅含 `grass`、`river` 的 pilot 地貌池和 `grass|river` 装饰池。
3. 用独立 Unity 预览场景组成固定 seed 的草地—河流地图，并通过 Editor 自检实际执行一次生成流程。
4. 用户确认后，把相同数据模型接入正式 `PCGMapGenerator`/`TotemMapService`，停止读取 edge/socket 数据。
5. 所有主题迁移完成且验证通过后，再归档旧切片 catalog；回滚时恢复旧入口即可。

## Open Questions

无。其他地貌列表、图块选择规则与装饰放置规则在草地—河流试制确认后另行展开。
